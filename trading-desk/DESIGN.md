# 值班交易台 · 24 小时自动化交易流程设计

> 一套面向 24 小时市场的交易运维流程：确定性执行、可量化的风险额度、一条走完才能上钱的资金阶梯。
> 结论先说：**AI 可以值夜班，但不能决定方向。**

---

## 0. 三条结论

1. **能设计，但要先承认一个反转**：经营里 AI 的失误是"多花了钱"，市场里 AI 的失误是"对手方正在赚你的钱"。市场是零和且对抗性的，所以系统设计的重心不是"更聪明的信号"，而是**让错误无法致命**。
2. **平台选加密永续合约（Binance / OKX），不是因为好赚，而是因为可自动化**：7×24 连续、API 与模拟盘成熟、无 T+1、无涨跌停、合约规格统一。代价是杠杆、资金费、交易所对手方风险和监管问题。
3. **AI 不进热路径**。下单执行必须是确定性规则；大模型放在研究、复盘、异常归因和值班助手里。把 LLM 接进下单链路，等于给系统装了一个会随机延迟 2 秒、还会被新闻标题注入的零件。

> 本文是工程与流程设计，不构成投资建议。文中的收益、夏普、回撤均为**设计目标与示例口径**，不是承诺。

---

## 1. 为什么不能照搬「AI 自动经营」的直觉

很多人对自动交易的想象是：写一个很聪明的模型，让它 7×24 去找机会。
这个直觉在"AI 经营一门生意"里大致成立，在交易里会致命——因为两边的最优策略是相反的。

| 维度 | 自动化经营 | 金融市场 |
| --- | --- | --- |
| 收益来源 | 创造增量价值，正和 | 对手方的亏损，零和（扣费后负和） |
| 反馈周期 | 天到周 | 毫秒到月，且噪声极大 |
| 错误代价 | 赔钱、封号 | 爆仓、穿仓、本金归零 |
| "机会"的性质 | 需求缺口，可验证 | 统计规律，会衰减、会失效、会被套利掉 |
| 人的角色 | 审批预算与发布 | **审批风险额度**，而不是审批每一笔单 |
| 失败模式 | 内容违规、投放跑飞 | 过拟合、前视偏差、流动性枯竭、交易所宕机 |

所以在交易里，管束不能是"审批流程"，而是**三种硬约束**：

- **风险闸**：不是"这次花多少"，而是"这笔最多亏多少"。
- **上线闸**：策略不能"写完就实盘"，必须走完资金阶梯。
- **合规与对手方闸**：不碰客户资金、密钥不给提币权限、辖区合法。

## 2. 平台选型

### 2.1 为什么是加密永续

24 小时自动化的三个硬条件：**连续交易、程序化下单、可回测的同一套接口**。

| 市场 | 连续交易 | API 成熟度 | 主要障碍 |
| --- | --- | --- | --- |
| 加密永续 | 7×24 | 高（REST/WS/模拟盘） | 杠杆、资金费、交易所风险、监管 |
| 美股 | 6.5h + 盘前盘后 | 高（Alpaca/IBKR） | PDT 规则、结算、做空约束、时区 |
| 全球期货 | 近 24×5 | 中高（IBKR/CTP） | 保证金、合约换月、夜盘流动性 |
| 外汇 | 24×5 | 中 | 点差、经纪商对手方风险 |

结论：**能 7×24 跑的第一选择是加密永续**；如果你的资金与身份只适合传统市场，就用 IBKR 做期货/多资产，或用 Alpaca 做美股日内，然后接受"每天只有几个小时可交易"。

### 2.2 Binance 还是 OKX

| 维度 | Binance | OKX | 说明 |
| --- | --- | --- | --- |
| 流动性 | 主流币最深 | 主流币接近，长尾略薄 | 大资金优先 Binance |
| 账户结构 | 现货/合约分仓清楚 | **统一账户 + 组合保证金** | 做基差、跨品种，OKX 更顺手 |
| 模拟环境 | 有测试网，稳定性一般 | **模拟盘完整、贴近实盘** | 纸面阶段体验差异明显 |
| API 限频 | 严格但透明 | 严格但透明 | 都要做令牌桶与退避 |
| 费率高阶 | VIP 阶梯深 | 类似 | 高频策略先算清返佣 |
| 可用性 | 部分地区受限 | 部分地区受限 | 见 §9 合规 |

**建议组合**：主账户 OKX（统一账户适合 delta 中性套利与组合保证金），备账户 Binance（流动性最好、跨所基差需要两家）。两个都开，是为了做**跨所基差**和**故障切换**，不是为了分散"信仰"。

> 境内提示：中国大陆境内，虚拟货币相关业务活动属于非法金融活动，个人参与交易不受法律保护，境内也没有合法的交易通道。下面所有设计只在**允许该业务的辖区**成立。

## 3. 系统架构：七层

```
┌──────────────────────────────────────────────────────────────┐
│ 7  研究与上线  回测 → 前向 → 纸面 → 金丝雀 → 实盘 → 扩仓      │
├──────────────────────────────────────────────────────────────┤
│ 6  监控与值班  心跳/死手开关/告警/runbook/事故复盘            │
├──────────────────────────────────────────────────────────────┤
│ 5  清算与记账  成交对账 / PnL 归因（alpha·成本·资金费）        │
├──────────────────────────────────────────────────────────────┤
│ 4  执行 OMS    订单状态机 / 幂等 clientOrderId / 限频 / 只减仓 │
├──────────────────────────────────────────────────────────────┤
│ 3  组合与风险  ★风险闸：前置校验 + 实时敞口 + 回撤调速         │
├──────────────────────────────────────────────────────────────┤
│ 2  特征与信号  point-in-time 存储 / 版本化 / 无前视            │
├──────────────────────────────────────────────────────────────┤
│ 1  数据        行情 L2/成交/资金费/持仓量 + 合约元数据          │
├──────────────────────────────────────────────────────────────┤
│ 0  基础设施    时钟同步 / 同区部署 / WS 断线重连 / 序列号校验   │
└──────────────────────────────────────────────────────────────┘
```

几条工程铁律：

- **订单幂等**：每笔订单带唯一 `clientOrderId`，超时重试用同一个 ID，绝不重复开仓。
- **状态以交易所为准**：本地状态机只做推断，每 30 秒对账一次；不一致以交易所成交为准并告警。
- **退出永远 reduce-only**：平仓单只能减仓，防止反向开仓。
- **死手开关**：策略进程每 1 秒向交易所/本地守护进程发心跳，连续 5 秒缺失 → 撤全部挂单 + 平掉可平仓位。
- **时钟**：NTP 漂移 > 200ms 直接拒绝下单（签名时间窗会失效）。
- **部署位置**：与交易所同区域机房（东京/新加坡），目标下单往返 P50 < 80ms；不参与需要微秒级竞争的做市。

## 4. 三道闸的具体数值

### 4.1 风险闸（前置 + 实时）

| 层级 | 限制 | 触发动作 |
| --- | --- | --- |
| 单笔 | 单笔风险 ≤ 权益 0.25%（按止损距离折算） | 拒单 |
| 单策略 | 日亏 ≤ 权益 1%；单策略杠杆 ≤ 3x | 策略暂停至次日 |
| 组合 | 日亏 ≤ 2%；名义敞口 ≤ 60%；保证金占用 ≤ 40% | **全部平仓 + 停机** |
| 回撤阶梯 | -5% 减半 / -8% 只减仓 / -12% 停机复盘 | 自动执行，不询问 |
| 集中度 | 单标的 ≤ 20%；同相关性簇 ≤ 40% | 拒单 |
| 流动性 | 单笔 ≤ 1% 价格带内挂单量的 5% | 拆单或拒单 |

关键点：**止损由系统执行，不由人执行**。人可以改额度，但不能在盘中绕过额度。

### 4.2 上线闸（资金阶梯）

| 阶段 | 资金 | 时长 | 通过条件 |
| --- | --- | --- | --- |
| 研究 | 0 | — | 假设可证伪，写明失效条件 |
| 回测 | 0 | ≥ 2 年，含牛熊各一轮 | 样本外 ≥ 30%；含双边成本（taker 0.1% + 滑点 3bp 主流 / 15bp 长尾） |
| 前向 | 0 | 4 周 | 滚动前向，参数不再改动 |
| 纸面 | 0（实时行情） | 4 周 | 模拟成交与实盘偏差 < 25% |
| 金丝雀 | 风险预算 1% | 4 周 | 实盘夏普 ≥ 回测 50%；滑点 ≤ 1.5× 模型 |
| 实盘 | 10% | 按月 | 指标不劣化，相关性 < 0.7 |
| 扩仓 | 逐月 ×2 | — | 直到触及容量上限（≤ 盘口深度的 5%） |

任何一步不达标：**回到上一步，不许"再观察一周"**。这句话是整套流程里最值钱的一条。

### 4.3 合规与对手方闸

- API Key **只给交易权限，禁止提币**，绑定 IP 白名单。
- 资金分散在两个交易所，单所不超过总资金 50%（对手方风险）。
- 盈利定期提出到自托管地址/银行，不在交易所长期沉淀。
- 若代人交易：需要资管/投顾牌照；**代客理财无牌照 = 非法集资高发区**。
- 不承诺收益、不公开喊单、不做"跟单社区"（多数辖区视为投资建议或资管）。

## 5. 机会从哪里来

不要从"预测下一根 K 线"开始——那是所有散户量化亏钱的起点。先做**结构性错价**，它们不依赖预测：

| 类型 | 逻辑 | 现实收益（示例） | 容量 | 主要风险 |
| --- | --- | --- | --- | --- |
| 资金费套利 | 永续做空 + 现货做多，收资金费 | 年化 6–12%（牛市中段更高） | 大 | 资金费转负、现货借币成本、交易所风险 |
| 跨所基差 | 同标的两所价差回归 | 年化 5–10% | 中 | 提币延迟、价差不回归、两边保证金 |
| 期现基差 | 交割合约贴水/升水 | 年化 4–9% | 中 | 交割日流动性 |
| 长尾做市 | 小币种宽点差挂单 | 取决于返佣与库存风险 | 小 | 库存被单边打穿、下架 |
| 趋势/动量 | 4h 以上周期，波动率过滤 | 不稳定，靠赔率不靠胜率 | 中 | 震荡市连续止损 |
| 统计套利 | 相关性配对均值回归 | 不稳定 | 小 | 相关性突变 |

**判断标准**：如果一个策略说不清"钱是从谁的口袋里来的"，它大概率是过拟合。

## 6. AI 到底干什么

| 位置 | 做什么 | 不做什么 |
| --- | --- | --- |
| 热路径（毫秒级） | 无。确定性代码 + 规则 | 不调用大模型 |
| 研究 | 读论文/研报、生成假设、写回测代码、整理因子 | 不直接决定仓位 |
| 监控 | 日志聚类、异常检测、告警降噪 | 不自动改参数 |
| 值班 | 事故初判、拉取上下文、生成复盘草稿 | 不碰下单接口 |
| 复盘 | PnL 归因、滑点分析、策略衰减报告 | — |

一句话：**AI 是研究员和值班员，不是交易员。**

## 7. 成本与延迟预算

| 项目 | 量级 |
| --- | --- |
| 手续费 | 合约 taker 约 0.05%、maker 约 0.02%（以官方为准） |
| 资金费 | 每 8 小时一次，年化 -30% ~ +50% 波动 |
| 滑点 | 主流币 1–3bp；长尾 10–30bp |
| 延迟 | 同区云主机 P50 50–100ms；不参与 HFT |
| 回测成本假设 | 比真实成交更悲观：多算 1–2bp |

**成本必须进回测**。一个"回测年化 40%、扣完成本 -5%"的策略，是这条路上最常见的尸体。

## 8. 会杀死你的七件事

1. **过拟合**：试了 500 组参数，挑出最好的一组。→ 用 deflated Sharpe、保留样本外、限制试验次数。
2. **前视偏差**：用了当时还拿不到的数据（尤其资金费、收盘价、上币公告）。
3. **交易所风险**：宕机、插针、强平引擎异常、提币暂停。FTX 不是黑天鹅，是常态风险。
4. **流动性幻觉**：回测按中间价成交，实盘打穿三层盘口。
5. **杠杆与相关性**：以为分散了，其实四个仓位都在赌同一个方向。
6. **运维事故**：密钥泄露、重复下单、断线后状态不一致、误删生产库。
7. **监管与身份**：辖区不允许、代客无牌照、税务未申报。

## 9. 合规红线

- **境内**：虚拟货币相关业务活动属非法金融活动；不面向境内用户宣传、不使用境内支付通道、不设境内运营主体做这件事。
- **境外**：交易所需 KYC；若管理他人资金，需 VASP/MSB 或当地资管牌照；营销素材不得出现"稳赚""保本""AI 躺赚"。
- **产品化**：如果把这件事做成平台，**卖工具不卖收益**——做"交易运维与风控系统"，不碰客户资金、不代客下单、不做信号订阅。这是唯一能规模化又不踩牌照线的位置。

## 10. 90 天落地

| 周 | 做什么 | 交付物 |
| --- | --- | --- |
| 1–2 | 数据与 point-in-time 回测框架；先复现"资金费套利"这个已知答案 | 能跑通的回测 + 成本模型 |
| 3–4 | OMS + 风险闸 + 对账 + 监控 | 纸面交易系统 |
| 5–8 | 纸面跑 4 周，校准滑点/延迟/断线 | 纸面报告，偏差 < 25% |
| 9–10 | 金丝雀 1% 资金 | 实盘对照报告 |
| 11–13 | 扩仓或淘汰；补 runbook、死手开关演练 | 运行手册 + 事故演练记录 |

**验收标准不是"赚了多少"，而是"在最坏的一天，系统是否按设计停了"。**

---

## 11. 明确不做

1. 不做"AI 预测涨跌"的对外产品。
2. 不做代客理财、不做跟单社区、不做收益承诺。
3. 不做需要微秒级竞争的 HFT（散户基础设施打不过）。
4. 不上高杠杆（组合名义敞口硬上限 2x，套利另计）。
5. 不在单一交易所放超过一半资金。
6. 不在回测里"优化到好看"再上线。
