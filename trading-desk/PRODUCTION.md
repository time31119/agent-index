# 实盘上线清单 · Go / No-Go

> 现在这个站是**设计说明书 + 演示页**。实盘需要的是一个能承担资金的系统——两者差的不是几个功能，而是八类工程能力。
> 这份清单的用法很硬：每一项只有三种状态——**未做 / 做了但没验证 / 已验证（有证据）**。只数"已验证"。

---

## 0. 三条放行原则

1. **先能安全地停，再谈赚钱。** 系统在极端情况下的停机能力，优先级高于任何策略收益。
2. **没有证据的"应该没问题"，一律算未做。** 证据 = 日志、演练记录、对账截图、压测报告。
3. **P0 未全绿，不上真钱。** P0 里有一项没验证，额度就是 0。

## 1. 账户与权限（P0）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 1.1 | 独立子账户 | 只跑本系统，不与手工交易混用 |
| 1.2 | API Key 禁提币 | 创建时明确关闭提币；交易所侧不可逆确认 |
| 1.3 | IP 白名单 | 只允许固定出口 IP（含备用 IP） |
| 1.4 | 密钥托管 | 存 KMS / Vault，不落代码库、不进日志；90 天轮换一次 |
| 1.5 | 交易所账号安全 | 独立邮箱、2FA、登录与提币告警 |
| 1.6 | 资金分散 | 单所 ≤ 总资金 50%；盈利按月提出 |
| 1.7 | 出金双人复核 | 出金地址白名单 + 两人确认 |
| 1.8 | 主体与辖区 | 有明确的法律意见：在哪个辖区、以什么主体、做什么业务 |

**常见事故**：Key 权限给多了、Key 进了 Git 历史、白名单加了 0.0.0.0/0。

## 2. 执行正确性（P0）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 2.1 | 幂等下单 | 每笔订单固定 `clientOrderId`；超时重试复用同一 ID，绝不生成新 ID |
| 2.2 | 订单状态机 | 覆盖 NEW / PARTIALLY_FILLED / FILLED / CANCELED / EXPIRED / REJECTED 与**未知态**；未知态只允许撤单与对账，不允许新开仓 |
| 2.3 | 精度与取整 | 按合约 `tickSize` / `stepSize` 取整；金额与数量用定点数（decimal），禁止浮点 |
| 2.4 | 模式校验 | 启动时断言仓位模式（单向/双向）、保证金模式、杠杆倍数与配置一致，不一致直接拒绝启动 |
| 2.5 | 撤单-成交竞态 | 撤单返回"已成交/不存在"时，以交易所回报为准，不当作撤单成功 |
| 2.6 | 部分成交 | 剩余量、均价、手续费按逐笔成交累计，不覆盖 |
| 2.7 | 限频 | 令牌桶 + 权重预算；429/418 指数退避；触发限频即降级为只减仓 |
| 2.8 | 只减仓退出 | 所有平仓单 `reduceOnly`，防止反向开仓 |
| 2.9 | 自成交防护 | 同账户挂单冲突检测 |
| 2.10 | 维护窗口 | 读取交易所系统状态；维护期间不新开仓，且不误判为"订单丢失" |

**常见事故**：网络超时后重试生成了两笔单（双倍仓位），这是实盘第一天最容易踩的坑。

## 3. 数据与时钟（P0）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 3.1 | 序列号连续性 | WS 增量数据校验 `prevSeq`，断点用快照重建，重建期间不交易 |
| 3.2 | 重连策略 | 指数退避 + 抖动；重连成功后先对账再恢复交易 |
| 3.3 | 时钟 | NTP/PTP 同步；漂移 > 200ms 拒绝下单并告警 |
| 3.4 | 行情延迟 | 监控"交易所时间戳 - 本地接收时间"P99，超阈值自动降档 |
| 3.5 | 深度快照 | 保留盘口快照用于流动性校验与滑点估计 |
| 3.6 | 数据落盘 | tick/盘口归档，支持事后逐笔重放复盘 |

**常见事故**：断线 30 秒，本地还以为仓位没变，恢复后按旧状态继续下单。

## 4. 风控与熔断（P0）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 4.1 | 前置风控 | 单笔/单策略/组合/集中度/流动性五级校验，拒单要记录原因 |
| 4.2 | 实时敞口 | 含未成交挂单的名义敞口，不是只算已成交 |
| 4.3 | 回撤阶梯 | -5% 减半 / -8% 只减仓 / -12% 停机，自动执行并通知 |
| 4.4 | 死手开关 | 策略心跳缺失 5s → 撤全部挂单 + 平可平仓位 |
| 4.5 | 单写者 | 同一账户同一时刻只允许一个实例下单（分布式锁 + 主备仲裁） |
| 4.6 | 三级人工闸 | 暂停 / 只减仓 / 全平，**按钮可用、有演练记录、有权限控制** |
| 4.7 | 操作审计 | 谁、何时、改了什么额度，全部留痕且不可篡改 |

**常见事故**：主备切换时两个实例同时活着，同时开仓。

## 5. 对账与记账（P0）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 5.1 | 仓位对账 | 每 30s 本地 vs 交易所，差异即冻结并告警 |
| 5.2 | 余额对账 | 可用/冻结/总权益三项逐一核对 |
| 5.3 | 成交对账 | 拉取交易所成交流水，逐笔比对本地订单 |
| 5.4 | PnL 归因 | 拆成 alpha / 手续费 / 资金费 / 滑点四项，缺一项就无法判断策略是否真的有效 |
| 5.5 | 资金费与返佣 | 单独入账，不计入策略 alpha |
| 5.6 | 日结单 | 每日自动生成，可导出 CSV 供税务与复盘 |

**原则**：**对账不平就停**。宁可少赚一天，不要带着错误的仓位过夜。

## 7. 策略与资金（P1，进钱之前必须完成）

| # | 检查项 | 通过标准 |
| --- | --- | --- |
| 7.1 | 证据链 | 回测 ≥ 2 年、样本外 ≥ 30%、纸面 ≥ 4 周、金丝雀 ≥ 4 周 |
| 7.2 | 成本口径 | 回测按悲观成本（taker 双边 + 滑点），实盘滑点不得超模型 1.5 倍 |
| 7.3 | 容量 | 估算能吃到盘口深度的比例，写进配置上限 |
| 7.4 | 淘汰条件 | 书面化：连续 30 天低于回测一半 / 回撤超限 / 相关性 > 0.7 |
| 7.5 | 资金规则 | 单策略预算、总预算、再平衡规则、加仓节奏（每次 ≤ ×2） |

## 9. 上线后 30 天

- **每日**：实盘 vs 纸面的滑点、成交率、夏普对照；对账零差异。
- **每周**：PnL 归因复盘，看 alpha 是否被成本吃掉。
- **触发降档**：滑点 > 1.5× 模型 / 连续 3 日负 alpha / 任何一次对账不平。
- **禁止**：上线前 30 天内修改策略参数（改了就要重新走纸面）。

## 10. 工程量与人力（从零开始）

| 角色 | 人数 | 说明 |
| --- | --- | --- |
| 后端 / 执行 | 1 | 订单状态机、风控、对账 |
| 数据 / 研究 | 1 | 行情、回测、指标 |
| SRE / 运维 | 0.5 | 部署、监控、演练 |
| 交易负责人 | 0.5 | 资金、额度、Go/No-Go |

**时间**：从零到金丝雀约 **8–12 周**；到可以放量，通常还要再 8 周。
如果有人告诉你两周能上实盘，他要么没做过，要么不打算对你的钱负责。

## 11. 最容易被低估的六个坑

1. **重复下单**：超时重试没做幂等，第一周就会遇到。
2. **状态不同步**：断线后按本地状态继续跑，仓位和以为的不一样。
3. **精度与取整**：数量 0.30000000000000004，订单直接被拒或超卖。
4. **撤单竞态**：以为撤掉了，其实成交了，反手又开一单。
5. **维护窗口**：交易所升级，系统把"查不到订单"当成"订单失败"。
6. **人**：凌晨三点没人看告警，或者有人手动改了额度没记录。
