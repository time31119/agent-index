# APEX · 智能体与算力平台
## 规划设计方案 v1.0

> 一句话：**APEX 是智能体经济的 App Store，也是它们的算力电网与结算层。**
>
> 本文件说明市场判断、平台模型、产品与信息架构、技术架构、信任与治理、商业模式、冷启动与路线图。配套的可交互站点为目标态演示（2029），规划起点为 2026 Q4。

## 0. 一页摘要

| 项目 | 内容 |
|---|---|
| 平台定位 | 智能体与算力的双边市场 + 运行时 + 信任层 |
| 核心用户 | 开发者 / 算力供应商 / 企业业务与 IT / 专业消费者 |
| 解决什么 | 智能体「发现难、部署难、算不清账、不敢用于生产」 |
| 差异化 | 唯一同时提供 **多模型、多算力、统一计量、可验证信任、企业治理** 的市场 |
| 北极星指标 | 每周付费完成任务数（Paid Task Completions, PTC） |

**为什么是平台而不是目录：** 只有运行时在平台内，才能计量、评测、审计与结算；只有同时握住供给与算力，才能承诺「任务一定被完成」。

## 1. 定位：重新打包三件事

App Store 的成功不是「软件很多」，而是把三件事绑进同一块玻璃：

1. **发现**：用户不需要知道开发者是谁，就能找到可信的软件。
2. **支付**：一次绑定，全球扣款、退款、分账、税务。
3. **信任**：系统级沙箱、权限清单、审核与下架机制。

智能体时代，这三件事重新碎片化：模型厂有自己的商店，云厂有自己的市场，Agent 框架有自己的 Hub，企业在内部拼装权限、审计与账单。结果是：

- 开发者要对接 5 个渠道，分别处理定价、支付与合规；
- 用户要在 6 个入口之间比价，无法比较「完成同一任务」的真实成本；
- 法务无法回答：这个智能体能碰我的什么数据？出了问题谁负责？

**APEX 的判断：** 把「发现、算力、计量、结算、信任」重新打包成一层中立基础设施。不站队模型，不站队云，只对交易双方负责。

### 1.1 我们不做什么

| 不做 | 原因 |
|---|---|
| 训练基础模型 | 与模型厂竞争，失去中立性；资本效率极低 |
| 自建大规模 GPU 云 | 重资产、价格战；聚合与调度才是价值所在 |
| 自营头部智能体 | 与开发者争利，破坏供给信任 |
| 通用聊天入口 | 与需求方（模型厂助手）正面竞争，且不产生交易数据 |
| 抓取式目录 | 无运行时、无计量、无责任，只是流量生意 |

### 1.2 北极星指标

**PTC（每周付费完成任务数）**，而不是 GMV、安装量或智能体总数。

- 安装可以刷；
- GMV 可以补贴；
- 只有「付费且被判定完成」的任务，同时证明需求真实、供给可靠、结算闭环。

## 2. 市场机会

### 2.1 三个市场正在合并

| 市场层 | 2026 | 2030E | CAGR | 可交易比例 |
|---|---:|---:|---:|---:|
| 智能体分发与订阅 | $18B | $180B | 78% | 55% |
| 推理与训练算力 | $210B | $620B | 31% | 35% |
| 企业智能体编排与治理 | $6B | $48B | 68% | 70% |
| **TAM** | **$234B** | **$848B** | — | — |

> 示意性估算，用于说明量级与结构，不构成预测。

- **SAM**（跨供应商、可标准化交易）：约 $180B。
- **SOM**（三年可触达）：约 $12B GMV。

### 2.2 钱在哪里

1. **佣金不是全部。** 智能体的成本大头是推理与工具调用；只收 15% 佣金无法覆盖平台提供的算力、运行时与合规价值。
2. **企业按「工作」与「合规等级」付费。** 不是按席位买软件，而是按完成的任务、SLA 与审计能力买。
3. **长尾决定网络效应。** Top 50 智能体贡献 60% GMV，但「任何任务都能被满足」的感知来自长尾。

### 2.3 为什么是现在

- **模型商品化**：头部模型差距缩小，路由、成本与合规比「最强模型」更重要。
- **推理成本下降**：过去 18 个月单位 token 成本下降约 92%，按任务收费首次具备正毛利。
- **协议标准化**：MCP / A2A 让工具、记忆与智能体可组合，供给不被单一框架锁定。
- **企业进入生产期**：预算要求权限、审计、SLA 与赔付，这些是单个开发者提供不了的。
- **算力碎片化**：Neocloud 产能时而过剩、时而短缺，跨区调度存在明确效率空间。

## 3. 用户与场景

| 角色 | 核心任务（JTBD） | 痛点 | 平台价值 |
|---|---|---|---|
| 独立开发者 | 把能力变成可持续收入 | 分发、支付、算力、合规全要自己做 | 85% 分成、自助上架、算力补贴 |
| Agent 工作室 | 运营多个智能体并增长 | 评测、版本、企业销售、留存分析 | 工作室后台、联合营销、企业通道 |
| 企业业务负责人 | 用智能体完成具体工作 | 采购周期长、效果不可验证 | 试用、评测、按任务付费 |
| 企业 IT / 安全 | 管住权限、数据与账单 | 黑箱、越权、影子 AI | Passport、SSO、审计、预算 |
| 算力供应商 | 提高 GPU 利用率 | 获客难、结算慢、利用率波动 | 调度网络、计量结算、需求池 |
| 专业消费者 | 快速完成高价值任务 | 不知道选哪个、怕被坑 | curated 商店、真实评价、退款保障 |

### 3.1 关键洞察

企业不是不愿为智能体付费，而是**不愿为不可验证的结果承担生产风险**。平台的第一价值不是「更多选择」，而是「更低信誉成本」。

```
/blueprint              平台规划：市场、架构、商业、路线图
```

### 4.2 全局导航

- 一级导航：智能体 / 算力 / 控制台 / 开发者 / 平台规划。
- 全局搜索（⌘K）：跨智能体、GPU、页面搜索，支持键盘上下选择与回车直达。
- 账户入口：登录 / 开始使用。
- 移动端：折叠为菜单 + 搜索图标。

### 4.3 设计原则

1. **Editorial first**：像一本杂志，而不是一个后台。大字号、留白、克制的颜色，让「智能体」显得可信而不是玩具。
2. **证据优先**：每一个宣传语旁边，都有可验证的数字（评分、审计项、SLA、真实价格）。
3. **一个主行动**：每个页面只引导一个动作（探索、部署、发布、购买算力）。
4. **价格透明**：把成本估算器放在算力页，而不是「联系销售」。
5. **不假装**：演示数据明确标注为示意，不伪造客户 logo 或真实报价。

## 5. 核心用户流程

### 5.1 需求方：发现 → 试用 → 部署 → 计量 → 续费

1. **描述任务**：自然语言输入，平台解析为任务类型、预算、区域与合规约束。
2. **匹配组合**：返回「智能体 + 算力 + 模型」的组合，而不是单个智能体。
3. **沙箱试用**：14 天 / 500 次任务，行为与成本可见。
4. **权限确认**：逐项授予 scope，高风险动作二次确认。
5. **一键部署**：选择区域、副本、预算；运行时自动扩容。
6. **按秒计量**：每个任务生成账单明细与证据链。
7. **续费或退出**：按使用数据推荐升级；数据可导出，不锁定。

### 5.2 企业采购：6–10 周

需求描述 → 合规预检 → 沙箱验证 → 合同与数据处理协议 → 私有目录上线 → 季度业务复盘。

### 5.3 开发者：manifest → 评测 → 定价 → 上线

1. 写 `apex.yaml`（模型、工具、权限、算力、定价）。
2. 平台生成运行时与权限清单。
3. 200 个脱敏真实任务自动评测 + 安全扫描。
4. 人工复核高风险品类。
5. 选择区域与定价，全球上线。
6. 月度结算，85% 分成。

### 5.4 算力采购：区域 → 型号 → 估算 → 预留/现货

1. 选择区域（延迟、数据驻留、价格系数）。
2. 选择 GPU 型号与数量。
3. 估算器给出月度成本与节省空间。
4. 选择按需 / 预留 / 现货。
5. 部署或绑定到智能体。

## 6. 产品模块规格

### 6.1 智能体商店（Store）

**目标：** 让用户在 3 分钟内找到能完成任务的智能体。

- 搜索：名称、能力、开发者、任务描述。
- 筛选：类别、定价方式、是否验证、评分。
- 排序：推荐、评分、安装量、价格。
- 卡片：身份、评分、价格、权限摘要、编辑标签。
- 详情：能力、运行示例、权限、定价、评测、版本、同类推荐。

**验收标准：** 90% 的测试用户能在 3 分钟内完成一次「找到并开始试用」。

### 6.2 算力市场（Compute）

**目标：** 把 GPU 采购从「销售流程」变成「自助结账」。

- 9 个区域，价格系数透明。
- 8 种型号，按需价 / 现货价 / 余量实时展示。
- 成本估算器：型号 × 数量 × 时长 × 区域 × 现货。
- 预留 / 现货 / 边缘三种供给形态。
- 供应商列表与 SLA 承诺表。

**验收标准：** 用户无需联系销售即可得到可信的月度成本，误差 < 5%。

### 6.3 控制台（Console）

**目标：** 一个页面管住智能体、算力、权限与钱。

- KPI：支出、运行中智能体、任务量、P95 延迟。
- 支出图表与预算告警。
- 部署列表与实时计量流水。
- 四步部署向导：选智能体 → 绑算力 → 配权限与副本 → 确认。
- 部署日志与回滚。

**验收标准：** 新用户从零到第一个生产部署 < 10 分钟。

### 6.4 开发者中心（Studio）

- 声明式 manifest 与 CLI。
- 沙箱评测报告（200 任务、行为录屏）。
- 定价工具（订阅 / 按量 / 席位 / 企业）。
- 分账、税务、发票、退款。
- 增长工具：A/B、推荐位申请、企业线索。

### 6.5 信任中心（Trust）

- Agent Passport：身份、代码哈希、模型、工具、权限、数据边界。
- 审计日志与任务回放。
- 评测成绩与历史。
- 事件披露与赔付记录。

### 6.6 企业私有市场（Private Market）

- 内部智能体目录（可包含自研与外部）。
- SSO / SCIM / 角色权限。
- 数据驻留与 BYOK。
- 专属容量与 99.99% SLA。
- 季度用量与 ROI 报告。

## 7. 平台架构

### 7.1 五层架构

| 层 | 组件 | 关键职责 |
|---|---|---|
| 体验层 | 商店、算力、控制台、工作室、企业后台 | 发现、购买、部署、管理 |
| 商业层 | 目录、搜索推荐、定价、计费、分账、税务 | 把供给变成可交易 SKU |
| 信任层 | Agent Passport、策略引擎、APEX Bench、审计、风控 | 让陌生交易可信 |
| 运行时 | Agent Runtime、工具网关、记忆、编排、可观测 | 真正把任务跑完 |
| 算力层 | 调度器、GPU 池、模型服务、KV 缓存、边缘 | 以最低成本满足 SLA |
| 数据层 | 事件流、计量账本、特征库、对账 | 一份账，四处用 |

### 7.2 三个不可替代的服务

**① 计量账本（Metering Ledger）**

每一次模型调用、工具调用、GPU 秒写成不可变事件，带 task_id、agent_version、region、pricebook_version。账本同时服务于：向用户收费、向开发者分账、向算力商结算、向监管证明。

**② 调度器（Scheduler）**

多目标优化：成本、延迟、合规（数据驻留）、供给稳定性。支持现货抢占前 30 秒信号、跨区迁移、模型与硬件联合选型。

**③ Agent Passport**

平台签名的 manifest：开发者主体、代码哈希、模型清单、工具与权限、数据边界、评测成绩。运行时每次启动校验签名，防止「上架一个、运行另一个」。

### 7.3 核心数据模型

| 实体 | 关键字段 | 说明 |
|---|---|---|
| Agent | id, maker_id, category, status | 智能体主档 |
| AgentVersion | version, image_hash, manifest, eval_score | 不可变版本 |
| Deployment | agent_version, region, replicas, budget | 运行实例 |
| Task | input, output, status, cost, latency | 一次任务 |
| MeterEvent | task_id, resource, qty, unit_price | 计量事件 |
| PriceBook | sku, region, tier, effective_at | 价目表版本 |
| Payout | payee_id, period, amount, tax | 分账 |
| Passport | scopes, data_policy, signature | 信任凭证 |

### 7.4 API 草图

```
GET  /v1/agents?q=&category=&verified=
GET  /v1/agents/{id}
POST /v1/deployments            { agent_id, gpu, region, replicas }
GET  /v1/tasks/{id}
POST /v1/estimates              { gpu, count, hours, region, spot }
GET  /v1/metering?from=&to=
POST /v1/publish                (manifest)
```

### 7.5 技术选型建议

- 前端：Next.js / React，SSR 用于商店 SEO；设计系统用 CSS 变量 + 组件库。
- 后端：Go 或 Rust 负责调度与计量（高并发、低延迟）；TypeScript 负责商业层。
- 数据：Postgres（交易）、ClickHouse（计量与行为）、Kafka（事件）、Redis（配额）。
- 运行时：Kubernetes + WASM / gVisor 沙箱，Temporal 编排长任务。
- 策略：OPA / Cedar 做权限与合规策略；所有策略可版本化、可回放。
- 多区域：主动-主动读，区域写隔离；账本按区域分片，全球对账。

| 目录搜索 P95 | < 120ms |
| 部署到可服务 | < 90s（P95） |
| 计量事件延迟 | < 5s |
| 账本一致性 | 100%（T+1 对账零差异） |
| 可用性 | 99.95%（平台）/ 99.99%（企业） |

## 8. 信任、安全与治理

### 8.1 上架三道门

1. **静态扫描**：依赖漏洞、密钥泄漏、恶意网络目标、提示注入特征。
2. **动态沙箱**：200 个真实任务，观察越权、外传、成本失控、欺骗行为。
3. **人工复核**：金融、医疗、法律等高风险品类，以及所有申请支付权限的智能体。

### 8.2 权限与数据

- 最小权限 scopes，未声明即拒绝，运行时不可临时提权。
- 高风险动作（支付、终端、摄像头）默认关闭，二次确认。
- 数据不用于训练；默认 30 天删除；支持 BYOK 与区域驻留。
- 全链路审计：参数、结果、耗时、费用，可回放、可导出。

### 8.3 责任矩阵

| 角色 | 责任 |
|---|---|
| 平台 | 身份核验、审计、运行时隔离、SLA、事件披露 |
| 开发者 | 功能真实性、权限最小化、漏洞修复、内容合规 |
| 部署方 | 使用场景合规、数据授权、人工复核高风险决策 |

SLA 未达标自动抵扣；安全事件 72 小时内披露；争议由外部审核委员会裁决。

### 8.4 区域合规

| 法域 | 核心要求 | 产品化动作 |
|---|---|---|
| 欧盟 | AI Act 分级、GPAI 透明度、GDPR | 高风险人工复核、模型卡、EU 独立区域 |
| 中国 | 生成式 AI 备案、内容安全、数据出境 | 隔离域、本地持牌主体、内容过滤 |
| 美国 | 州隐私法、金融/医疗监管 | 牌照校验、删除权、州附录 |
| 海湾/新加坡 | 数据本地化、伊斯兰金融 | 本地机房、额外审计 |

### 8.5 治理原则

- 平台不自营同类智能体；推荐位含商业合作必须标注「推广」。
- 排序逻辑每年由第三方审计。
- 开发者可在 5 个工作日内申诉；处理理由公开（脱敏）。
- manifest 与评测数据可导出，避免锁定。

## 9. 商业模式与单位经济

### 9.1 收入结构

| 收入流 | 计价 | 毛利率 | 三年占比 |
|---|---|---:|---:|
| 智能体交易佣金 | GMV 的 15%（企业 10–20%） | ~92% | 38% |
| 算力撮合与转售 | GPU 小时价差 8–12% | ~22% | 41% |
| 企业平台订阅 | $50k–$500k / 年 | ~80% | 12% |
| 评测与认证 | $5k–$50k / 次 | ~70% | 5% |
| 推理 API 加价 | 模型成本 + 5–8% | ~15% | 4% |

### 9.2 单位经济（示意）

**头部智能体（年 GMV $1.2M）**

- 平台佣金：$180k
- 算力消耗 $420k，价差约 $46k
- 净收入：$226k
- 分摊运行时、支付、客服、合规：$70k
- 贡献毛利：$156k（69%）

**企业客户（年付 $180k + $600k 算力）**

- 净收入：约 $240k
- CAC：$60k
- 回收期：3 个月
- 三年 NRR 目标：135%

### 9.3 三年财务（示意）

| 指标 | Y1 · 2027 | Y2 · 2028 | Y3 · 2029 |
|---|---:|---:|---:|
| GMV | $80M | $620M | $2.4B |
| 净收入 | $14M | $112M | $432M |
| 混合抽成率 | 17.5% | 18.1% | 18.0% |
| 毛利 | $8.4M | $71M | $294M |
| 经营现金流 | −$18M | −$6M | +$74M |

假设：头部供给留存 85%、算力价差 9%、企业客户 180 家（Y3）、退款与坏账 2.5%。

### 9.4 定价原则

1. **不赚暗差价**：算力价格与市场实时同步，平台只收明示服务费。
2. **按结果可退**：任务未完成不收费；企业可按季度对账。
3. **区域定价**：按购买力与合规成本差异定价，不做全球统一定价。
4. **补贴透明**：算力补贴写进合同，不与排名挂钩。

## 10. 冷启动与增长

### 10.1 先做窄，再做深，最后做宽

| 阶段 | 策略 |
|---|---|
| Wedge 品类 | 企业级深度研究 / 代码智能体：任务价值高、结果可验证、愿为可靠性付费 |
| 供给侧 | 100 家设计伙伴：12 个月 0 佣金、算力补贴、联合打磨评测，换取 3 个月品类 exclusivity |
| 需求侧 | 不买流量；与 IDE、浏览器、模型厂做分发合作；用「任务完成率」做案例 |
| 流动性 | 90% 的付费需求在 10 分钟内被满足；否则补供给，而不是继续拉需求 |

### 10.2 为什么供给先行

需求可以被补贴瞬间点燃，但没有可靠供给，第一波用户会永久流失。供给打磨周期 6–9 个月，必须提前启动。早期团队应像「制片人」：一个个谈下头部智能体，帮它们跑通评测、定价与企业部署。

### 10.3 前 100 个智能体决定平台气质

如果它们都是「聊天玩具」，企业不会来；如果它们是「能完成工作并留下证据的工具」，企业会自己找上门。

## 13. 竞争与护城河

| 玩家类型 | 多模型 | 多算力 | 统一计量 | 信任审计 | 企业治理 |
|---|---|---|---|---|---|
| 模型厂商店 | 否 | 否 | 部分 | 弱 | 弱 |
| 云市场 | 部分 | 自家 | 部分 | 中 | 强 |
| 开源 Agent Hub | 是 | 否 | 否 | 弱 | 弱 |
| 算力聚合平台 | 否 | 是 | 是 | 弱 | 弱 |
| **APEX** | **是** | **是** | **是** | **是** | **是** |

**四层护城河：**

1. **流动性**：双边同时在线，匹配效率随规模提升。
2. **数据**：任务—模型—算力—结果四元组，形成路由与定价优势。
3. **信任**：审计记录、评测历史、事故处理声誉，需要时间积累。
4. **工作流嵌入**：权限、账单、合规流程一旦接入，迁移成本高（但必须可导出）。

## 14. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 模型厂纵向整合 | 商店与算力被自营 | 多模型中立、企业治理、跨云算力 |
| 云厂价格战 | 算力价差被压缩 | 轻资产聚合、收入向软件倾斜、调度效率取胜 |
| 安全事件 | 平台信任受损 | 默认沙箱、权限最小化、保险池、24h 披露 |
| 供给质量失控 | 刷单、演示造假 | 平台复跑评测、按结果排序、行为监控 |
| 监管碎片化 | 扩张变慢 | 区域隔离、本地持牌伙伴、合规即代码 |
| 双边冷启动失败 | 供需互相等待 | 供给先行、单品类 wedge、设计伙伴 exclusivity |
| 算力供给中断 | SLA 违约 | 多供应商、跨区迁移、预留缓冲 |

## 16. 设计系统

### 16.1 品牌

- 名称：**APEX**（顶点）。
- 标志：一座由三条边构成的极简山峰，象征「供给、需求、算力」在顶点汇合。
- 语气：克制、具体、有证据；不喊「颠覆」，只说「完成」。
- 主张：**The Intelligence Marketplace** / 智能体时代的 App Store。

### 16.2 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#F4F2EC` | 主背景（暖纸白） |
| `--ink` | `#0B0C0E` | 主文字 / 深色区 |
| `--accent` | `#2440FF` | 主行动、链接、强调 |
| `--live` | `#0E9F6E` | 运行中、正向指标 |
| `--amber` | `#B45309` | 警示、风险 |
| `--line` | `rgba(11,12,14,.11)` | 分隔线 |

深色区使用 `#08090B` 背景、`#F5F2EA` 文字，靠留白与细线分隔，不使用大面积渐变。

### 16.3 字体

- 西文 / 数字：SF Pro Display、Inter、system-ui。
- 中文：PingFang SC、Noto Sans SC、Microsoft YaHei。
- 强调：Songti / Iowan Old Style 斜体，仅用于品牌句与关键名词（如「App Store」「全世界」）。
- 层级：Display 46–88px / H2 32–54px / 正文 15–16px / 标签 10–12px；标题字距 -0.03 ~ -0.05em。

### 16.4 栅格与间距

- 内容最大宽度 1240px，边距 26px（移动 18px）。
- 8pt 基础栅格；区块间距 72–118px；卡片内边距 20–24px。
- 圆角：卡片 14–22px，按钮全圆角，图标 12–14px。
- 阴影只用于浮层与 hover，不用装饰性阴影。

### 16.5 组件

按钮（4 种）、筛选 chip、徽章、Agent 卡、GPU 卡、数据表、代码窗、终端、步骤条、标签页、命令面板、Toast、进度条、时间轴、架构层。

### 16.6 动效

- 只用于「状态变化」：hover 抬升 2–4px、面板淡入 0.25s、数字 1.4s 计数。
- 尊重 `prefers-reduced-motion`：关闭位移与计数，直接呈现终值。
- 不使用自动播放视频、不制造焦虑式闪烁。

### 16.7 可访问性

- 正文对比度 ≥ 4.5:1；焦点环 2px accent。
- 所有交互可用键盘；命令面板支持上下与回车。
- 图标按钮有 `aria-label`；表格有表头；表单有 label。
- 移动端触控目标 ≥ 40px。
