# AI 雷达 · 实时追踪 AI 新应用

一个**零后端、零构建、零依赖**的静态站点：打开就是一个聚合了 13 个信源的 AI 情报面板，浏览器每 5 分钟自动拉取一次最新内容。

```
ai-radar/
├── index.html          # 页面结构
├── assets/
│   ├── style.css       # 全部样式，无框架
│   ├── sources.js      # ★ 信源配置（只改这个文件就能增删源）
│   └── app.js          # 抓取 / 解析 / 渲染 / 缓存
└── README.md
```

## 一、立刻跑起来

**方式 A（最快）**：双击 `index.html`，浏览器直接打开。

**方式 B（推荐，避免个别浏览器的 file:// 限制）**：

```powershell
cd ai-radar
python -m http.server 8080
# 然后访问 http://localhost:8080
```

打开后你会看到：顶栏的更新时间与刷新倒计时、按「新应用 / 开源 / 社区 / 资讯」分类的卡片流、搜索框（按 `/` 聚焦）、「只看新增」开关、底部可展开的信源健康状态。

快捷键：`/` 搜索、`R` 刷新、`Esc` 退出输入。

## 二、做成"独立网站"

三个文件目录整体上传即可，不需要 Node、不需要数据库、不需要服务器进程。

**GitHub Pages**
1. 新建仓库，把 `ai-radar` 里的内容推到根目录
2. Settings → Pages → Source 选 `main` / `(root)`
3. 一分钟后拿到 `https://<用户名>.github.io/<仓库名>/`

**Cloudflare Pages / Netlify**
把整个文件夹拖进控制台即可，构建命令留空，输出目录填 `/`。

**任意对象存储**（OSS / COS / S3）
开静态网站托管，上传后把 `index.html` 设为默认首页。

> 因为没有任何后端，整站就是几个文本文件，任何能托管静态页的地方都能放。

## 三、实时性是怎么实现的

| 环节 | 做法 |
|---|---|
| 抓取 | 浏览器端 `fetch`，页面打开时立即拉一次，之后每 5 分钟一次 |
| 全失败兜底 | 直连不行自动依次尝试 3 个公开 CORS 代理 |
| 首屏速度 | 上次结果存在 `localStorage`，打开即渲染，再静默更新 |
| 切回标签页 | 数据比刷新间隔旧就立刻补拉一次 |
| 新增提示 | 与本地「已读」记录比对，新条目带绿点 + 计数 |

**边界要说清楚**：这是"浏览器开着才更新"。页面关掉、手机锁屏，就不会再拉。要做到**无人值守也持续更新**（比如每天早上打开就是新的、还能推送到微信/飞书），需要加一个定时任务——见第六节。

## 四、改信源

只改 `assets/sources.js`。加一条：

```js
{
  id: 'my-feed',            // 唯一标识，改了等于重新计已读
  name: '我的源',
  group: 'news',            // app | open | community | news
  kind: 'rss',              // rss | hn | github | hf
  url: 'https://example.com/feed.xml',
  enabled: true
}
```

`group` 决定它落在哪个标签页。删源就是把对应对象删掉或设 `enabled: false`。

**已知会失效的源**：Product Hunt、机器之心、量子位的 RSS 偶尔会改地址或加反爬；OpenAI / arXiv 的 feed 格式有时不标准。底部「信源状态」里标 ✕ 的就是当次没抓到的，鼠标悬停能看到具体错误。这类失败不影响其他源。

调整节奏在 `assets/sources.js` 末尾的 `RADAR_CONFIG` 里：

```js
refreshMinutes: 5,     // 想更实时就调到 2～3，注意别被限流
timeoutMs: 12000,      // 单请求超时
proxies: [ ... ],      // CORS 代理，按顺序尝试
```

## 五、为什么不用后端 / 数据库

因为你的需求是"看最新资讯"，不是"存全量历史"。纯前端方案换来的是：部署成本为零、不需要维护服务器、不怕被刷、数据不落库没有合规负担。代价是受 CORS 和公开代理的稳定性影响——这正是第六节要解决的。

## 六、升级路线（按需选）

**① 摆脱 CORS 代理（最值得做）**
加一个 GitHub Actions 定时任务（每 30 分钟），在服务端跑 Node 抓取、生成 `data/latest.json` 提交回仓库；页面优先读这个本地 JSON。代理从此只是兜底，稳定性大幅提升。

**② 无人值守 + 推送**
同一套脚本加一步：把当天新增条目推到飞书/钉钉/Telegram 机器人。这样你根本不用打开网页。

**③ AI 摘要与打分**
抓到的标题过多时，用一次 LLM 调用做去重、分类、打"值不值得看"的分，只展示 Top 20。需要 API key（DeepSeek / OpenAI 均可），成本约每天几分钱。

**④ 加数据源**
接入 Product Hunt 官方 API（需要 token）、X/Twitter List（需要 API）、Reddit 多板块、以及国内更多垂直源。

## 七、当前状态说明

这台机器的 shell 处于故障状态（连 `echo` 都返回 `0xC0000142`，Windows DLL 初始化失败），所以我**没能在这里启动服务、用浏览器实际跑一遍并截图**，也无法执行 `node --check`。

代码经过一轮独立静态审查，修掉了几个真问题：

- **Ctrl+R / Cmd+R 被劫持** —— 快捷键原先没排除修饰键，会把浏览器的"重新加载"变成刷新数据。已加 `ctrlKey/metaKey/altKey` 守卫。
- **刷新时列表塌陷** —— 原先每次只拿本轮已返回的条目替换整份列表，第一个源回来时列表会缩成一条再慢慢长回来。现在保留上一轮结果做底，按链接合并。
- **全源失败会清空缓存** —— 七个 RSS 全靠公共代理，集体失败时旧版会用空数组覆盖 `localStorage`，下次打开连缓存都没了。现在失败时保留旧数据、不写缓存。
- **去重键与已读键不一致** —— 同一链接出现在两个源里时，存活者由到达顺序决定，已读状态会丢。现在 id 只由链接派生，跨源一致。
- **摘要显示成 `<p>xxx</p>`** —— 原先"先剥标签再解实体"，转义过的 feed 正文会露馅。改成用 DOMParser 转纯文本（同时消掉了 innerHTML 注入面）。

第二轮专项核对后补修的：

- 块级标签之间不补空格会导致 `</p><p>` 两段文字粘成一个词，已在解析前补空
- 二次转义判定的时机不对，那一层剥不下来 —— 改成对原文判定后再剥一轮
- 缓存键升到 v4：条目 id 的派生规则变过，沿用旧键会把新旧两条同一文章当成两条
- 无路径只有 query 的 URL（`x.com?id=AbC`）不再被整串小写
- 缓存形状校验（`items` 不是数组就丢弃），避免脏数据在 `forEach` 上抛错
- 全源失败时不再刷新 `lastUpdated` 和缓存时间戳，状态栏不会把旧数据说成"刚更新"

**仍需你本机确认的**：在 `ai-radar` 目录下跑一次 `node --check assets/app.js`，然后双击打开看实际效果。如果白屏，先看浏览器控制台——最可能是某个源报错或代理被限流，而不是页面本身挂了；其次检查 `index.html` 是否与 `assets/` 平级。

## 八、重点推荐位（交易 EA / 短视频）

页面顶部并排两块常驻面板，配置在 `sources.js` 的 `window.SPOTLIGHTS`，每个面板声明从哪些 `group` 取内容、取几条：

```js
window.SPOTLIGHTS = [
  { id: 'ea',    title: '交易 EA · 加密 / 黄金', groups: ['ea'],    limit: 6 },
  { id: 'video', title: '短视频制作',            groups: ['video'], limit: 6 }
];
```

这些 `group` 的条目**只出现在面板里**，不进主信息流，避免同一张卡重复。

### 交易 EA · 加密 / 黄金

| 源 | 类型 | 说明 |
|---|---|---|
| r/algotrading 周榜 | Reddit RSS | 量化/EA 讨论热度最高的一批 |
| HN · MT5 | Algolia API | 英文技术圈的 MT5 / EA 讨论 |
| MQL5 官方 | RSS | 官方文章与社区动态，地址可能会变 |

**一个必须说明的限制**：MQL5 Market 没有公开的下载量接口或榜单页面，浏览器端抓取又会被 Cloudflare 拦住。所以这块**按发布时间排序**，标题下方也如实写了"MQL5 无公开下载榜单"，不伪装成下载榜。

如果你要真正的"下载量最大"榜单，只有一条可靠路径：加服务端定时抓取（GitHub Actions 跑 Node，抓 MQL5 Market 的排序页并存成 JSON）。要做的话我可以补。

### 短视频制作

| 源 | 排序依据 |
|---|---|
| HF 文生视频模型 | **下载量**（`pipeline_tag=text-to-video`，`sort=downloads`）|
| HF 图生视频模型 | **下载量**（`pipeline_tag=image-to-video`）|
| GitHub video-generation | star 数，近 14 天新建项目 |

这两块 HF 源是真·下载量排名，面板右侧会显示 `↓ 1.2M` 这样的数字。GitHub 那条按 star 排，混合面板里会排在 HF 后面——因为下载量数量级远大于 star。

想换成中文生态（抖音/快手热榜、剪映/可灵这类国内工具），需要额外接聚合站或 RSSHub，公网实例经常不稳，我没有默认放进去。

### 调参

- 面板只显示前 N 条 → 改对应 `limit`
- 加一个重点位 → 在 `SPOTLIGHTS` 里加一项，并给它专属 `group` 和对应信源
- 面板空了 → 看底部「信源状态」里 `ea-*` / `vid-*` 那几行，通常是 Reddit 或 HF 被限流
