PRODUCT BLUEPRINT · 2026.11 · HANGZHOU

从一句话，
到一条能起量的片子。

起量 QILIANG 是给大量中小业主的自动化营销短视频工具。它把一句话、模板、脚本、成片、配音、发布与复盘，收进一条足够简单、能规模化复制的流水线。

产品定位中小业主营销自动化 · SaaS
核心用户中小业主 / 门店 / 小电商
首期范围本地生活 + 电商带货
EXECUTIVE SUMMARY

AI 视频生成正在变成水电煤。真正稀缺的，不是「生成一条视频」，而是知道该拍什么、为每个平台改成什么样、发出去之后如何让它起量，以及把结果回流到下一条。

起量的答案不是再做一个模型超市，而是做一层「增长编排」：向上理解生意目标，向下调度模型、素材、账号与广告，中间用一条极简的工作流把复杂藏起来。

三条核心判断
  • 机会在分发与复盘生成能力会迅速同质化，工作流数据不会。
  • 拒绝虚假的「全自动」官方 API 能直发就直发，不能就半自动，不碰 RPA。
  • 用结果收费，而不是按次收费客户买的是到店、成交与增长，不是视频文件。
00

一页看懂：把复杂藏起来

产品、技术、商业与合规的最小共识。后面每一节，都是这一页的展开。

用户只需要回答三个问题：给谁看、想得到什么、在哪个平台发。剩下的，交给流水线。

PROBLEM

内容生产正在「去专业化」

商家知道要做短视频，但不知道拍什么；有素材，但不会剪；剪完了，不会为三个平台改；发出去了，不知道哪条有效。

SOLUTION

一条五步流水线

说清楚 → 选方向 → 做成片 → 适配审核 → 发布推流。默认自动，关键节点保留人的判断。

MOAT

越用越懂你的数据闭环

账号画像、品牌资产、发布记录、完播与转化，形成只属于这个客户的「内容基因」，而不是公共模型的通用能力。

一句话定位

给大量中小业主的自动化营销短视频工具。不是给专业剪辑师，也不是给内容团队；是给没有时间学拍摄、但每周都要为门店拉客的老板。不比谁生成的画面更炫，比谁能让内容更快、更稳、更有结果。

0.2 首期只做三件事

  • 一条能打的片子：30–60 秒，真实感优先，适合本地生活与轻电商，不追求电影级。
  • 三个平台的原生版本：抖音、视频号、小红书，各自重写标题、封面、字幕断句与节奏。

01

机会判断：生成在贬值，分发在升值

当每个人都能生成视频，竞争会回到内容行业的本质：选题、分发与复盘。

过去两年，短视频工具解决的是「能不能生成」。接下来三年，真正的问题是「生成什么，发给谁，怎么起量」。

1.1 四个正在发生的变化

SHIFT 01

供给爆炸，注意力更贵

AI 让内容供给以数量级增长。用户的注意力没有变多，平台的流量分配更依赖完播、互动与转化信号。

SHIFT 02

生成能力快速商品化

视频模型的能力差距在缩小，价格在下降。把「接入最多模型」当卖点，很快会被下一个模型发布抹平。

SHIFT 03

平台越来越「各自为政」

同一支片子不能直接复制到三个平台。比例、标题、封面、语气、音乐、合规规则都不同，原生适配成为刚需。

SHIFT 04

商家要的是结果，不是内容

客户不为「一条视频」付费，只为「到店的人」「成交的单」「涨起来的粉」付费。工具必须能回答结果。

1.2 现有工具的四个断点

断点现状客户实际感受
只会生成给提示词、出画面，但不知道什么选题值得拍。生成很酷，发出去没量。
不会适配一条 9:16 直接裁成 3:4，标题与封面不重写。小红书像抖音，视频号像广告。
发布割裂要么手动逐个平台发，要么用灰色 RPA 批量操作。费人、易封号、不可审计。
数据不回流后台只有播放量，没有「为什么」和下一条建议。每周都在重新猜。
客户不需要一个「更会生成」的工具，需要一个「更会判断」的搭档。

1.3 我们明确不做什么

1
不做模型超市不把几十个模型名丢给用户选。按任务路由，用户只选「更抓人 / 更快 / 更省」。
2
不承诺三平台全自动平台没有开放的能力，就用半自动 + 人工确认。不碰 RPA、不绕风控。
3
不做批量账号农场不做矩阵号批量注册、模拟互动、去重洗稿。短期增长，长期封号。
4
不自动花广告费推流计划可以自动生成，但预算提交与放量必须有人确认。
5
不抓取未授权内容趋势数据与素材必须来自官方 API、授权合作或客户自有资产。
6
不把「生成」当终点发布不是结束。没有数据回流与下一条建议，产品就只是一个玩具。
02

用户与场景：先服务「有生意的人」

不从泛创作者开始。先服务那些「内容直接关联收入」的人，付费意愿和反馈质量都更高。

平台服务的是大量中小业主，不是专业创作者。第一批客户不是「想学做视频的人」，而是已经有生意、每周必须发内容、但没有内容团队的人。

2.1 为什么先做本地生活

  • 需求具体：「让附近的人来店里」比「帮我做个人 IP」更容易定义成功。
  • 内容可复用：门头、老板、菜品、客人、地址，素材稳定，模板可沉淀。
  • 视频号有优势：本地信任、社交推荐、中老年人群，与本地生活高度匹配。
  • 可以面对面交付：早期用「 concierge（人工陪跑）」换真实反馈，比纯自助更快找到 PMF。

2.2 三个核心 JTBD

JTBD 01

「当我不知道拍什么时，给我一个现在就能拍、且和我生意有关的选题。」

不是热榜，是可执行。要包含场景、钩子、所需素材与拍摄难度。

JTBD 02

「当我没有团队时，帮我把一条片子做出来，并且三个平台都能发。」

不是生成一个片段，是交付一条能直接发布的成片。

JTBD 03

「当我发完之后，告诉我哪条有效、为什么、下一条怎么改。」

不是报表，是决策。要能直接变成下一条 Brief。

反直觉判断

不要先做「创作者的 Canva」。创作者对价格敏感、需求发散、流失快。先做「商家的内容操作台」：目标明确、预算明确、结果可衡量。

03

产品定义：一条流水线，而不是一堆按钮

默认路径只有五步。专业能力放在第二层，需要时再展开。

「简单」不是功能少，而是每一步只有一个主要决定，其余由系统给出可解释的默认值。

3.2 三条设计原则

PRINCIPLE 01

一句话开始

首页只有一个大输入框。用户不需要先选模型、比例、时长、风格。系统先给一个 80 分版本。

PRINCIPLE 02

渐进式复杂

默认「简易模式」：三步出片。需要时再打开「专业模式」：时间线、轨道、关键帧、品牌套件。

PRINCIPLE 03

人在回路

发布、预算、肖像、医疗金融等高风险内容必须人工确认。自动化不等于放弃责任。

关键设计

时间线 JSON 是唯一事实源。母版、9:16、3:4、1:1、不同标题与封面，都是从同一份时间线派生出来的「视图」。不要为每个平台单独维护一条片子。

界面收敛

工程上仍需要选题、模板、素材、设置这些能力，但用户界面只暴露 4 个操作页：工作台、创作、发布、数据。选题与模板作为工作台的入口，素材与设置收进弹层或后台，不再各占一个一级导航。

4.2 版本策略

  • P0（0–3 个月）：工作台、创作台、选题雷达、抖音 API 直发、视频号 / 小红书半自动、基础数据。
  • P1（3–6 个月）：品牌套件、团队审批、素材授权中心、多账号、推流计划、AI 复盘。

05

模型编排：不选模型，选结果

「整合所有顶尖大模型」不是把每个 API 都接一遍，而是让每个任务自动找到当下最合适的模型。

模型会不断更新、涨价、降价、下架。产品不能把未来押在某个模型上，要把未来押在路由能力与评测数据上。

产品判断

「模型超市」是伪需求。商家不关心 Kling 还是 Vidu，只关心「这条能不能发、像不像我家店、要不要加钱」。模型选择应该发生在系统内部，用评测与成本约束决定。

5.2 路由的五道闸门

1
任务分类脚本、分镜、图像、视频、语音、质检，各自有独立的候选集。
2
质量评分离线黄金集 + 在线反馈，按平台、行业、语言分层。
3
成本 / 时延预算单条视频有成本上限；超限自动降级到更便宜的路径。
4
合规与地域境内数据留在境内；涉及人脸、声音、医疗、金融时提高审核等级。
5
降级链主模型超时 / 失败 / 限流时，自动切换备选，并记录原因。
6
成本记账每次调用写入项目账本，能解释「这条视频为什么花了 18 块」。

5.3 评测与版本管理

  • 黄金集：500 条真实 Brief，覆盖 3 个平台、5 个行业、3 种时长；每月补充失败案例。
  • 双层评分：人类偏好（钩子、真实感、品牌一致性）+ 线上指标（3 秒留存、完播、互动、转化）。
  • Prompt Registry：每个提示词有版本、适用平台、变更记录与回滚能力。
  • 灰度：新模型先跑 5% 流量，不直接全量替换。
  • 可解释：每条成片记录「用了哪个模型、为什么选它、花了多少、失败几次」。

5.4 成本控制

视频模型的成本波动最大。产品必须默认「混合生产」，而不是「整条片子都用视频模型生成」。

60%

授权素材 + 动态图形

门头、环境、产品、空镜、字幕卡。成本低、真实感强、可控。

30%

AI 补镜头

只生成缺失的 3–5 秒镜头：转场、氛围、无法实拍的场景。

10%

数字人 / 口播

用于知识、测评、标准化内容。需肖像授权与 AI 标识。

06

数据与选题：没有「万能数据库」，只有授权数据网

「最顶流的短视频数据库」不是一个可以买到的文件。它是由趋势、素材、账号表现和内容结构组成的数据网。

真正可用的数据壁垒，不是「全网的视频」，而是「这批客户、这个行业、这三个平台」的私有表现数据。

C · 第一方发布记录、完播、互动、转化、评论、投放平台授权回传、客户上传、广告后台复盘、账号画像、下一条建议
D · 结构钩子、叙事、节奏、镜头、字幕、CTA对授权内容的结构化标注 + 模型理解爆款基因库、创意路线、模板

常见数据合作方：巨量算数、千瓜、新红、飞瓜、蝉妈妈、灰豚等。它们大多需要商务合作或授权账号，并不等于「有公开 API」。产品应把「数据源可用性」做成可配置的能力，而不是写死在代码里。

合规底线

不爬取未授权视频、不存储无授权原片、不把客户素材用于公共模型训练。趋势数据优先走官方 API 或商业合作；公开元数据只做聚合分析，不做原片复刻。

6.2 机会分：把「感觉」拆成可解释的因子

选题雷达不输出一个神秘分数，而是把六个因子摊开给用户看。这样用户知道「为什么推荐」，也允许手动调整权重。

FORMULA

Opportunity = 0.30 × 热度 + 0.20 × 增速 + 0.20 × 账号匹配 + 0.15 × 商业价值 + 0.15 × (1 − 竞争度) − 风险惩罚

因子怎么算用户看到的文案
热度话题播放 / 搜索 / 互动，按赛道归一化「近 24 小时热度 96」
增速24h / 7d 增长率，剔除异常峰值「还在涨，增速 38%」
账号匹配粉丝画像、历史内容、地域、价格带的相似度「和你的账号匹配 91」
商业价值品类、转化意图、客单价、团购 / 商品关联「适合到店 / 团购」
竞争度供给量、头部集中度、内容同质化程度「竞争低，仍有空位」
风险惩罚医疗、金融、绝对化用语、版权、肖像「合规风险低」或「需人工复核」

6.3 爆款基因库

不是存「爆款视频」，而是存「为什么有效」的结构化标签。每条参考内容被拆成可复用的结构，而不是可抄袭的文案。

07

一条能发布的片子，需要的是镜头、声音、字幕、节奏与品牌的协同，而不是一段 5 秒的惊艳画面。

不要用「一句话生成整条视频」作为默认路径。它的可控性、成本、一致性和合规性，都不适合商业内容。

7.4 为什么保留「人」

  • 真实性：本地生活的信任来自老板的脸、口音、停顿，AI 无法替代。
  • 判断力：哪句话能代表品牌、哪个梗不能开，只有人知道。
  • 责任：发布与投放涉及商业承诺，必须有人签字。

产品的目标不是「无人」，而是把人的时间从 3 小时压缩到 15 分钟：人只做选择、确认与表演，机器做检索、组装、渲染与检查。

08

发布与推流：诚实，是最强的产品能力

三个平台的开放能力不同。把「能」与「不能」说清楚，比承诺「一键全自动」更能建立长期信任。

截至 2026 年 11 月，抖音有官方视频创建接口；视频号公开 API 未见视频发布能力；小红书开放平台以商家 / 电商能力为主。产品必须按真实能力设计。

本文中的「推流」指短视频发布后的自然流量获取与付费加热（千川 / 聚光 / 视频号加热），不是直播场景的 RTMP 推流。

8.1 平台能力矩阵

平台内容形态发布能力推流 / 投放产品策略
抖音9:16，强钩子，快节奏，声音优先官方 API「创建视频」接口，需申请发布权限并遵守发布规范巨量千川 / 本地推 / 巨量引擎，需广告主或服务商资质API 直发 + 千川 / 本地推计划；首期重点
视频号9:16，信任与社交推荐，30–90 秒半自动公开 API 以直播、橱窗、留资、电商数据为主，未提供视频发布视频号加热 / 腾讯广告，需相应资质官方发布页 + 素材预填 + 人工确认

产品原则

能 API 的，绝不让你多点一次；不能 API 的，绝不假装能。发布按钮旁边直接标注「API 直发 / 半自动 / 草稿导出」，让用户在使用前就知道会发生什么。

8.2 四种发布适配器

A
官方 APIOAuth 授权、上传、标题、封面、定时、状态回调。首选，稳定可审计。
B
授权服务商通过平台认证的第三方服务商能力接入，需明确责任与数据边界。
C
半自动生成发布包，打开官方页面，素材预填，用户扫码 / 点击确认。
D
草稿导出导出视频、封面、标题、正文与话题，适配完全封闭的平台。

8.3 为什么不做 RPA 批量发布

  • 违反平台规则：模拟点击、批量账号操作、绕过验证，可能导致封号。
  • 不稳定：平台前端一改，全部失效；客服成本极高。
  • 不可审计：品牌客户无法接受「不知道用什么账号、在什么时候、发了什么」。
  • 不可规模化：真正的规模化来自官方能力与工作流，不是脚本。

8.4 发布后 72 小时

0–2 HOURS

冷启动观察

看 3 秒留存、完播、评论关键词。别急着投；先判断内容本身有没有信号。

2–24 HOURS

小额测试

用 3 个封面 / 钩子做小额测试；预算不超过总预算的 20%。

24–72 HOURS

放量或止损

胜出素材逐步加预算；连续低于基准则停，回到选题与脚本。

8.5 推流计划的安全阀

  • 默认不自动花钱：系统生成计划，预算提交必须人工确认。
  • 预算上限：单条、单日、单账号三级上限；超过阈值二次确认。
  • 素材合规：未过审、未标注 AI、授权不明的素材不能进入投放。
  • 止损规则：CPA / 播放成本连续 2 小时高于目标 1.5 倍，自动暂停并通知。
  • 归因诚实：平台数据、优惠码、落地页、到店核销分开呈现，不制造虚假 ROI。

9.2 极简原则

ONE SCREEN · ONE JOB

一屏只做一件事

工作台只负责开始，创作只负责改片，发布只负责发出，数据只负责看结果。每屏一个主按钮。

READABLE

字号优先于密度

正文 17px、按钮 16px、标签不低于 13px。宁可少放两张卡，也不把字压到 10px。

OPERATE FIRST

学习内容后置

蓝图、拆解、Paywall 说明、平台能力长文不进主界面。用户先完成操作，需要时再看。

9.3 设计系统

COLOR

纸 · 墨 · 朱

暖纸底 #F5F1E8，墨黑 #151310，朱红 #C84222，成功绿 #1C7A4F。不用荧光黄做小字，不用低对比的「黑底黄字」。

TYPE

大字号，少层级

正文 17px，按钮 16px，标签不低于 13px；标题 42–68px。宁可少放内容，不压缩字号。

MOTION

克制的 200ms

只用于页面切换、弹层和状态反馈。不做漂浮、发光、粒子。

颜色纪律

强调色只给主按钮与关键数字；正文与背景保持高对比；黄色不进入文字系统。第一版固定一套「纸墨」，不把主题切换放进主界面。

9.4 文案原则

  • 说人话：「这条视频适合视频号，标题我重写了」而不是「已完成多模态平台适配」。
  • 说真话：「视频号需要你确认」而不是「一键发布全平台」。
  • 说下一步：每个空状态、每个结果页，都给一个明确的下一步动作。
  • 不制造焦虑：不用「再不投就晚了」「最后 3 个名额」。

9.5 模板：把参考变成可执行结构

Mobbin 的价值不是「收藏截图」，而是把头部产品的流程、状态与 Paywall 拆成可比较的结构。产品界面只保留「模板缩略图 + 名称 + 使用」；拆解、来源、版权说明收进后台或帮助，不占主流程。用户先选模板，再填入自己的品牌内容，而不是从空白画布开始。

样板值得学不要照搬
TikTok · For You结果先行、3 秒信息缺口、全屏、单 CTA具体文案、音效、品牌视觉、达人肖像
Reels · Remix分屏参与感、原声对话、开放结尾原声版权、原片画面、他人表演
Shorts · Feed滑动承接、悬念、订阅 / 长内容导流订阅按钮位置、广告节奏的逐帧复制

一键生成的做法：把样板拆成「场景 / 钩子 / 证明 / CTA / Paywall」五个字段，生成时只替换品牌、素材、口播与平台参数。用户看到的不是「复制一条 TikTok」，而是「用这个结构，做我的内容」。

版权边界

Mobbin 是参考库，不是素材库。页面内只做结构示意，不嵌入原始截图；真实产品可配置 Mobbin 深链（需订阅）或自建样板库。不要把品牌 Logo、原片、原声、文案直接放进「模板」。

9.6 Paywall：不做阻断式收费

极简版不做阻断式 Paywall。会员入口只在侧栏，点开是自选的会员页；不拦创作、不拦发布、不弹窗打断。先把创作、发布、复盘跑通，再考虑更细的收费节点。下面是后续设计参考。

  • 租户隔离：行级权限 + 对象存储前缀隔离；机构版可独立桶。
  • 密钥管理：平台 OAuth token 加密存储，KMS 管理，定期轮换。
  • RBAC：管理员、编导、审核、投放、只读；按项目授权。
  • 审计日志：谁在什么时候发布了什么、改了什么、花了多少。
  • 数据保留：客户可导出、可删除；默认不用于公共训练。
11

合规与风控：不是法务附件，是产品功能

AI 标识、广告法、版权、肖像、平台规则。每一项都要变成发布前的检查项，而不是出事后的补救。

在内容行业，合规不是「不做坏事」，而是「能证明自己没做坏事」。产品要留下证据链。

11.1 AIGC 标识

  • 显式标识：在视频画面、标题或简介中，以用户可感知的方式标注「AI 生成」。
  • 隐式标识：在文件元数据中写入生成信息、服务提供者、内容编号。
  • 平台声明：发布时按平台要求勾选「AI 生成」相关选项。
  • 可配置但不可规避：法规或平台要求必须标识的场景，默认锁定开启；不提供静默移除，只允许选择「不发布」。

依据：国家网信办等四部门《人工智能生成合成内容标识办法》，2025 年 9 月 1 日起施行。具体执行以最新法规与平台规则为准。

11.2 广告与内容合规

AD LAW

「最」「第一」「国家级」「治疗」「根治」等高风险表达；医疗、金融、教育、保健品需额外资质与审核。

PLATFORM

平台社区规范

低俗、炫富、诱导互动、虚假承诺、未成年人保护、地域歧视、搬运抄袭。

COPYRIGHT

只使用可商用授权；记录授权编号与范围；AI 生成内容的商用条款逐家核对。

LIKENESS

肖像与声音

数字人、声音克隆必须取得本人书面授权；未成年人需监护人同意；提供撤回机制。

下一步：先做窄，再做深

这不是一个「一次性做完」的产品。先选一个场景，跑通一条闭环，再复制。

如果今天就要开始，只需要确认四个决定。

1
先做哪个 ICP？建议：杭州本地生活（餐饮 / 美业），有门店、有团购、有预算。
2
接受半自动发布吗？建议：接受。抖音 API 直发，视频号 / 小红书半自动，不碰 RPA。
3
先做「工具」还是「服务」？只做工具。早期陪跑只用于内部验证，不对外售卖；验证后把重复动作产品化。
4
自建还是调用？建议：模型全部调用，渲染与工作流自建；把工程放在可控与成本上。

15.1 未来两周

  • 第 1–3 天：访谈 5 个本地商家，确认「每周发什么、谁在发、花了多少钱、结果怎么算」。
  • 第 4–7 天：用现成工具手工交付 3 条视频，记录每一步耗时与失败点。
  • 第 8–10 天：把最重复的 3 个步骤做成脚本 / 模板；确定数据回传方式。
  • 第 11–14 天：做出可点击原型，找 3 个商家试用，收集「愿不愿意付 ¥699」的答案。
最后一句话

不要试图整合「所有」模型，也不要承诺「全自动」发布。把一条视频从 3 小时变成 15 分钟，把一次发布从 3 个后台变成 1 个工作台，把一次复盘从「感觉」变成「下一条 Brief」。这就足够成为一个好产品。
