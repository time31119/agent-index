# Mosaic 万象 · 产品规划

> **一句话**：Mosaic 是一个把「顶尖模型矩阵 + 真实产品设计库 + 原生 App 交付流水线」合成一间 AI 工作室的网站。用户从一句话、一张截图或一个流程开始，得到一个可以安装、可以上架、可以继续写代码的 App。

- 版本：v1.0（2026-11）
- 形态：Web 端 AI App Studio + 可导出的 Expo / React Native 工程
- 首发市场：中文独立开发者、产品设计师、出海小团队
- 代号：Mosaic / 万象

---

## 0. 一页纸

### 问题

2026 年，生成一个「能看的页面」已经不值钱。真正稀缺的是三件事：

1. **品味**：模型能写代码，但不知道什么界面在真实产品里有效。生成结果高度同质化，一眼「AI 味」。
2. **整合**：Claude、GPT、Gemini、DeepSeek、Kimi、Qwen 各有所长，但用户没有精力维护六套 API、六套提示词、六套账单。
3. **交付**：从网页 Demo 到一个能过审、能推送、能收款的 App，中间隔着原生能力、后端、构建、签名、商店素材和合规。

### 解法

Mosaic 把三件事做成一个闭环：

| 层 | 做什么 | 壁垒 |
|---|---|---|
| **Model Mesh** | 按任务把请求路由给最合适的模型，自动降级、比价、评审、留痕 | 评测数据 + 路由策略 + 成本曲线 |
| **Design Intelligence** | 接入 Mobbin 级真实产品界面库，把「参考」变成可执行的 Design DNA 与界面质检 | 设计模式图谱 + 生成结果与真实模式的对照数据 |
| **App Graph + Ship** | 用一份活的 App 图谱驱动界面、数据、接口与构建，最后一键上 TestFlight / App Store | 原生交付链路 + 可导出代码，不锁定 |

### 不做什么

- 不做「一句话生成一个玩具网页」的演示型产品。
- 不做另一个 Figma，也不做另一个 Cursor。
- 不训练自己的基础大模型；做模型之上的**调度、评测与工作流**。
- 不把用户锁在专有运行时里：导出的工程可以直接 `npx expo start`。

### 北极星指标

**每周成功交付到真实设备的 App 数**（TestFlight 构建或生产环境部署），而不是生成次数、token 数或停留时长。

## 1. 机会与判断

### 1.1 三个结构性变化

**变化一：模型能力过剩，且高度分散。**
2026 年 11 月的第一梯队已经不是一个模型，而是一组各有短板的模型：

- Gemini 4 Carbon 在综合智能指数上领先（59），但初期只向受限合作方开放；
- Claude Opus 5.5 紧随其后（58），Claude Fable 5 在 SWE-bench Verified 上达到 95%，但价格高、且有出口与拒答限制；
- GPT-6 Astra（57）与 GPT-6.1 Sol（55，$2/$10 每百万 token）覆盖了从旗舰到高性价比的区间；
- DeepSeek V4.1 Flash 以开源权重和极低成本覆盖高频迭代；
- Kimi K2.7 Code、Qwen4 在代码与中文场景各有优势；
- 图像侧，GPT Image 2.5、Nano Banana 2.1、Seedream 5.0、Qwen-Image 3.0 分工明确。

**结论**：单一模型套壳没有未来，**路由能力**才是产品能力。用户不需要「最强的模型」，需要「这件事上最划算的成功率」。

**变化二：设计参考成为生产资料。**
Mobbin 已经积累了 60 万+ 真实产品界面，并在 2026 年推出 MCP，让 AI Agent 可以直接检索、引用这些界面。它证明了：**agent 会写代码，但不知道什么已经奏效**。把真实产品的模式接进生成回路，是从「能跑」到「像产品」的分水岭。

**结论**：设计库不是灵感墙，而是**约束系统**。它应该参与生成、评审和验收，而不是生成完再去里面找图。

**变化三：移动端仍然是 AI 构建工具的空地。**
Lovable、Bolt、v0、Figma Make 的主战场是 Web。原生 App 涉及 Expo/SwiftUI、推送、相机、健康、支付、签名、商店审核，复杂度高一个量级，也因此更难被通用模型直接吞掉。

**结论**：先做「移动端原生交付」这个又脏又长的链路，反而能建立时间窗口。

### 1.2 竞品缺口

| 产品 | 强项 | 缺口（Mosaic 的机会） |
|---|---|---|
| Lovable / Bolt / v0 | Web 生成快、上手门槛低 | 移动端弱；单模型；模板感强；设计与真实产品脱节 |
| Replit | 完整云端 IDE、部署 | 不是设计工具；移动端交付链不完整；学习曲线陡 |
| Figma Make | 设计稿到原型 | 生产级代码与后端弱；原生构建缺失 |
| Mobbin | 最强的真实界面库 | 只提供参考，不参与构建 |
| Claude Code / Codex | 极强的代码 agent | 面向工程师；无设计库、无 App 级工作流 |
| 应用模板市场 | 便宜、成熟 | 不可改、不可扩展、千篇一律 |

**空位**：**移动端优先 + 设计证据驱动 + 多模型编排 + 可导出代码**。这四个条件的交集，目前没有强势玩家。

## 2. 产品定位

### 2.1 定位句

> 对**有产品判断、但不想被工程拖住的人**，Mosaic 是**一间由 AI 组成的 App 工作室**。它不像代码生成器那样只给你代码，而是像一支团队那样，先找证据、再定方向、再做出来、最后帮你上架。

### 2.2 三种入口，一个出口

- **一句话**：「做一个帮上班族坚持晨跑的习惯 App，安静、克制、不要游戏化。」
- **一张图**：上传截图 / Figma / 竞品页面，反推出组件、token 与交互。
- **一个流程**：「把注册到付费这 6 步补齐。」系统从设计库里找 3 个真实流程做参照，再生成。

出口只有一个：**一个可运行、可安装、可继续开发的 App 工程**。

### 2.3 产品原则

1. **Evidence before generation.** 每次生成关键界面前，必须先给出参考与理由；用户可以否决参考。
2. **Show the seams.** 模型、成本、置信度、引用来源全部可见，不做「魔法黑箱」。
3. **Editable at every altitude.** 一句话、一个组件、一行代码、一个数据库字段，都可以被人接管。
4. **Native or nothing.** 不以「响应式网页套壳」冒充 App；相机、推送、健康、定位、支付按需真实接入。
5. **Exit is a feature.** 一键导出干净工程；用户随时可以离开，这反而建立信任。
6. **Calm interface.** 工具本身要安静。内容（界面）负责表达， chrome 负责退后。

## 4. 核心体验

### 4.1 主流程：Idea → App（15 分钟到第一个可安装版本）

| 步 | 界面 | 系统动作 | 模型 |
|---|---|---|---|
| 1 | 工作台输入框 | 解析意图，识别平台、品类、关键能力 | GPT-6.1 Sol（快） |
| 2 | 澄清卡片（最多 5 问） | 只问会改变架构的问题：谁用、核心循环、要不要登录/支付/推送 | Claude Opus 5.5 |
| 3 | App Plan | 生成页面清单、数据模型、接口、风险点；可拖拽调整 | Claude Opus 5.5 / Gemini 4 |
| 4 | 设计方向（3 选 1） | 从设计库检索同品类真实界面，生成 3 个 Design DNA + 首屏预览 | Gemini 4（视觉）+ 图像模型 |
| 5 | 生成首屏 | 先做 3 个关键页面，不一次性生成 30 个 | Claude Fable 5 / Opus 5.5 |
| 6 | 真机预览 | Expo Go / TestFlight；可交互，不是视频 | — |
| 7 | 迭代 | 选中组件 → 自然语言改；或直接改代码 | DeepSeek V4.1（高频）/ Opus（难改） |
| 8 | 接后端 | 一键开通 Postgres、Auth、Storage、推送 | — |
| 9 | 构建 | EAS Build，自动签名，生成商店素材 | — |
| 10 | 上架 | 合规检查、隐私清单、审核备注、提交 | — |

**关键设计**：第 5 步刻意「少生成」。先生成 3 页，让用户在 90 秒内看到东西并可交互，比生成 30 页等待 10 分钟更能建立信任。

### 4.2 Screenshot → App

1. 上传 1–20 张截图 / Figma 链接。
2. 视觉模型做版面解析：安全区、层级、组件、字体、颜色、间距。
3. 生成 **Design DNA**（token + 组件映射 + 动效猜测），而不是直接吐代码。
4. 用户确认「哪些是要保留的品牌资产，哪些是要替换的」。
5. 生成可运行的 Expo 工程；每个组件带来源标注（对应截图区域）。
6. 设计 lint：字号层级、对比度、点击区域、平台规范、与参考的偏差。

### 4.3 设计库 → 应用到我的 App

- 浏览 60 万+ 真实界面，按平台、品类、界面元素、流程、颜色、年份筛选。
- 选中一个界面，不是「复制图片」，而是抽出**可执行模式**：
  - 布局骨架（几栏、什么层级）
  - 组件配方（卡片、进度、导航）
  - token（色、字、圆角、间距）
  - 动效（转场、反馈）
- 点击「应用到我的 App」→ 生成 3 个变体 → 在真机预览里对比。
- **反向能力**：上传自己的界面，问「它和同类头部产品差在哪」，得到带引用的差距报告。

### 4.4 Flow Completion（补全流程）

用户说「缺一个付费墙」。系统：

1. 检索同品类 30 个付费墙，聚类出 4 种模式（订阅卡 / 对比表 / 试用倒计时 / 按量付费）。
2. 结合产品数据（客单价、试用策略）推荐 1 种，说明理由。
3. 生成流程：触发点 → 付费墙 → 购买 → 恢复购买 → 失败态。
4. 自动接 RevenueCat / StoreKit，生成沙盒测试。
5. 产出 A/B 变体与埋点。

### 4.5 Ship（发布）

- 构建流水线可视化：冻结设计 → 代码生成 → 单测 → E2E → 构建 → TestFlight → 审核。
- 自动生成：App Store 文案、关键词、截图（多尺寸）、预览视频脚本、隐私营养标签、审核备注。
- 审核被拒时：读取 resolution center，定位条款，给出修改方案并重新构建。
- 发布后：崩溃、留存、付费漏斗回到工作台，成为下一轮迭代的输入。

## 6. 对象模型

```
Workspace
 ├─ Project (App)
 │   ├─ Platform: iOS / Android / Web
 │   ├─ DesignDNA (tokens, type, motion, references[])
 │   ├─ Screen[] (name, route, state, components[])
 │   ├─ Flow[] (trigger, steps[], success/failure)
 │   ├─ Component[] (variants, props, usage)
 │   ├─ DataModel[] (tables, fields, relations)
 │   ├─ Integration[] (auth, payment, push, analytics)
 │   ├─ Build[] (commit, artifacts, store status)
 │   └─ Run[] (agent run, model, cost, tokens, diff)
 ├─ LibraryCollection[] (saved references, team boards)
 ├─ RoutingPolicy[] (task → model chain, budget)
 └─ Member[] (role, seat)
```

**App Graph 是单一事实源**。界面、代码、数据库、接口、测试都从它派生；任何一方被人工修改，都要回写到图谱。这避免了「聊天记录是唯一需求文档」的常见崩塌。

**Run 是一等公民**。每次 Agent 执行都记录：任务类型、候选模型、实际模型、输入摘要、输出 diff、耗时、成本、人工是否采纳。这是路由 eval 和团队审计的原料。

## 7. Model Mesh：把「所有顶尖模型」变成一条供应链

> 详细路由表与算法见 [`model-mesh.md`](./model-mesh.md)。

### 7.1 设计原则

1. **任务级路由**，不是项目级绑定。一个 App 的生成会经过 6–12 个不同任务。
2. **质量优先，成本约束**。先满足质量阈值，再在阈值内选最便宜的；不是反过来。
3. **可解释**。每次选择都告诉用户「为什么是这个模型」，并允许覆盖。
4. **可降级**。供应商 429 / 5xx / 地域限制时，50ms 内切备用，用户无感。
5. **可评估**。每个 workspace 有自己的采纳率数据，路由随数据变好。
6. **可合规**。代码敏感的企业可以把某类任务固定到自托管 DeepSeek / Qwen。

### 7.2 任务 → 模型（2026-11 首发配置）

| 任务 | 主模型 | 备用 | 理由 |
|---|---|---|---|
| 意图解析 / 澄清问题 | GPT-6.1 Sol | Gemini 3.5 Flash | 便宜、快、足够准 |
| 产品规划 / 信息架构 | Claude Opus 5.5 | Gemini 4 Carbon（如可用） | 长上下文、结构化强 |
| 设计方向 / 视觉理解 | Gemini 4 系列 | GPT-6.1 | 原生多模态，界面理解最好 |
| 首屏与关键页面生成 | Claude Fable 5 | Claude Opus 5.5 | SWE-bench Verified 95%，复杂 UI 一次成型率高 |
| 高频组件迭代 | DeepSeek V4.1 Flash | Gemini 3.5 Flash | 成本极低，适合几十次小改 |
| 大规模变体 / 文案 | GPT-6.1 Sol | Qwen4 Plus | 吞吐与中文表现平衡 |
| 截图转代码 | Gemini 4 系列 | GPT-6.1 | 视觉定位与版面还原 |
| 设计评审（多模型投票） | Opus 5.5 + Gemini 4 + GPT-6.1 | — | 降低单模型审美偏差 |
| 测试生成 / QA | GPT-6.1 Sol | Gemini 3.5 Flash | 终端与工具调用强 |
| 中文文案 / 本地化 | Qwen4 Plus | DeepSeek V4.1 | 中文语感与成本 |
| 图标 / 插画 / 商店图 | GPT Image 2.5 / Nano Banana 2.1 | Seedream 5.0 / Qwen-Image 3.0 | 按「文字准确性 / 写实 / 成本」分流 |
| 代码库长上下文分析 | DeepSeek V4 Pro | Gemini 4 | 1M 上下文，成本低 |

**关于「所有」**：首发接入 8 家供应商、12–15 个模型，覆盖 95% 的任务分布；每月根据公开榜单 + 站内 eval 更新。产品文案说「持续接入最强模型」，而不是「所有模型」。

### 7.3 路由算法（简化）

```python
def route(task, ctx):
    candidates = registry.filter(
        capability=task.capability,
        context>=task.tokens,
        region_ok=ctx.region,
        data_policy=ctx.policy,
    )
    for m in candidates:
        m.score = (
            0.55 * m.quality[task.type]      # 站内采纳率 + 公开基准
          + 0.20 * m.speed_score
          + 0.15 * m.cost_score
          + 0.10 * m.reliability
        )
    best = max(candidates, key=lambda m: m.score)
    if best.cost_estimate > ctx.budget_left:
        best = cheapest_above_threshold(candidates, ctx.quality_floor)
    return best, fallback_chain(candidates)
```

**冷启动**：用公开基准 + 人工标注的 500 个任务做初始权重；上线后 4 周内切换到站内数据为主。

**评审委员会**：对「设计方向」「付费墙」「Onboarding」等高价值决策，并行调用 3 个模型，按 rubric 打分，再由一个便宜的模型汇总。成本增加约 3 倍，但只用于 <5% 的步骤。

### 7.4 成本示例（一个中等复杂度 App，首次生成）

| 阶段 | 调用 | 估算成本 |
|---|---|---|
| 澄清 + 规划 | 8 次 Sol / Opus | $0.35 |
| 设计方向 + 参考检索 | 3 次 Gemini 4 + 6 张图 | $0.60 |
| 3 个首屏生成 | 3 次 Fable 5 | $2.40 |
| 20 次组件迭代 | 20 次 DeepSeek V4.1 | $0.18 |
| 测试 + 修复 | 12 次 Sol | $0.30 |
| 商店素材 | 6 张图 + 文案 | $0.25 |
| **合计** | | **≈ $4.1** |

按 Pro $19/月、每月 3 个 App 计算，模型成本约 $12，毛利率约 37%；通过缓存、路由降级与批量折扣可提升到 60%+。**这就是为什么路由不是技术细节，而是商业模式。**

## 8. Design Intelligence：把 Mobbin 从「参考」变成「约束」

### 8.1 三层能力

**L1 检索（Search）**
- 自然语言 + 结构化筛选：平台、品类、界面类型、UI 元素、流程、颜色、年份、地区。
- 以图搜图：上传自己的界面，找同构的真实界面。
- 结果不是图片列表，而是带标签的**模式卡片**：布局、组件、信息密度、语气。

**L2 解构（Deconstruct）**
- 视觉模型把界面拆成：栅格、层级、组件、token、动效线索。
- 输出 **Design DNA**：
  ```json
  {
    "color": {"bg": "#F4F1E8", "ink": "#171714", "accent": "#D9F45B"},
    "type": {"display": "28/1.05/-0.04", "body": "14/1.5"},
    "radius": {"card": 20, "button": 14, "sheet": 28},
    "density": "airy",
    "motion": {"enter": "spring(0.82, 24)", "press": "scale(0.97)"},
    "patterns": ["ring-progress", "streak-badge", "bottom-tab-4"]
  }
  ```

**L3 约束（Constrain）**
- 生成时把 DNA 作为硬约束注入 prompt 与代码模板，而不是事后「美化」。
- 生成后跑 **Design Lint**：
  - 对比度 < 4.5:1
  - 点击区域 < 44×44
  - 字号层级超过 5 级
  - 同屏主按钮 > 1
  - 与选定参考的布局偏差 > 阈值
  - 使用了平台不推荐的控件
- 输出不是「打分」，而是**可执行的修复建议 + 一键应用**。

### 8.2 数据来源与合规

这是产品最敏感的部分，必须前置设计：

1. **优先官方合作**：与 Mobbin 签订 API / MCP 商业授权，按调用量或席位分成。产品内明确标注 "Design references powered by Mobbin"。
2. **只存元数据与缩略图**：不缓存原图、不重建原始界面、不把参考图直接拼进用户成品。
3. **不训练**：未经授权，不用参考数据训练任何模型；只做检索与上下文注入。
4. **可退出**：品牌方可以通过流程下架；企业版可关闭外部参考，只用自己的私有库。
5. **用户内容隔离**：用户上传的截图仅用于当前项目，不进入公共库。
6. **归属可见**：每个生成界面都能展开「参考来源」，列出贡献了模式的真实产品。

> 如果无法与 Mobbin 达成授权，Plan B 是自建 5–10 万条精选界面库 + 与独立设计师/机构分成，产品叙事从「60 万」调整为「人工策展的高信号参考」。这会削弱壁垒，但不影响产品成立。

### 8.3 差异化：从「像」到「有效」

Mobbin 解决「看起来像真的」，Mosaic 要再往前一步：**这套模式在你的场景里是否有效**。

- 接入用户 App 的留存、转化、付费数据（经授权）。
- 把「参考模式 → 实际指标」做成匿名化的行业基准。
- 当用户选择某种 Onboarding 时，提示：「同品类中，这个模式的中位完成率是 62%，另一种是 74%。」
- 这是长期数据壁垒，也是定价从工具转向「增长伙伴」的依据。

## 9. 设计系统（摘要）

> 完整规范见 [`design-system.md`](./design-system.md)。

- **气质**：编辑部式的安静 + 工程感的精确。大量留白、发丝线、等宽字标签、真实界面作为唯一高饱和元素。
- **色彩**：暖纸白 `#F1EFE7`、墨黑 `#0A0A09`、酸性青柠 `#D5F23F` 作为唯一强调色；模型品牌色只以 6px 圆点出现。
- **字体**：无衬线 display（Inter Tight / Geist 回退到系统）+ 等宽 metadata（SF Mono / JetBrains Mono）+ 中文 PingFang / HarmonyOS Sans。
- **圆角**：卡片 16、按钮 12、手机 44、弹层 24。
- **网格**：1440 基准，12 栏，24px gutter；设计库 5 列，工作室三栏 260 / fluid / 360。
- **动效**：180–240ms，`cubic-bezier(.2,.8,.2,1)`；Agent 输出用逐字流；画布切换用 0.96→1 的轻微缩放，不做夸张弹跳。
- **图标**：1.5px 线性，圆头；不用彩色 emoji 作为功能图标。

## 10. 技术架构

```
┌─────────────────────────────────────────────────────────────────────┐
│ Web (Next.js)                                                        │
│  - Studio canvas (React + Tailwind + Framer Motion)                  │
│  - 实时协作 (Yjs / Liveblocks)                                       │
│  - 代码编辑器 (Monaco) / 设备预览 (iframe + Expo Snack)               │
└───────────────┬─────────────────────────────────────────────────────┘
                │ tRPC / WebSocket
┌───────────────▼─────────────────────────────────────────────────────┐
│ API / Orchestrator (Node + Python)                                   │
│  - App Graph service (Postgres + JSONB)                              │
│  - Run queue (Temporal / BullMQ)                                     │
│  - Model Mesh (LiteLLM 兼容网关 + 自研路由)                          │
│  - Design Intelligence (向量库 + 模式图谱)                            │
│  - Billing / Credits (Stripe)                                        │
└───────┬───────────────────────┬───────────────────────┬─────────────┘
        │                       │                       │
┌───────▼────────┐     ┌────────▼────────┐     ┌────────▼────────────┐
│ 代码沙箱        │     │ 构建             │     │ 数据面               │
│ Firecracker /  │     │ EAS Build        │     │ Neon Postgres        │
│ E2B / Daytona  │     │ Xcode Cloud      │     │ Supabase Auth        │
│ 每次 Run 隔离   │     │ GitHub Actions   │     │ R2 / S3              │
└────────────────┘     └─────────────────┘     └─────────────────────┘
```

### 关键选型

- **生成目标**：Expo (React Native) + TypeScript + NativeWind；需要原生模块时生成 Swift/Kotlin 插件。理由：一套代码双端、热更新、EAS 构建成熟、可导出。
- **代码沙箱**：Firecracker microVM，预热池，冷启动 < 800ms；每次 Agent run 独立文件系统，网络默认关闭，只允许白名单。
- **实时预览**：Web 端用 iframe + WebContainer 做快速预览；真机用 Expo Go / TestFlight。
- **数据**：项目图谱 Postgres；素材 R2；向量库 pgvector（初期够用）。
- **可观测**：OpenTelemetry；每次 run 记录模型、token、成本、延迟、采纳；按 workspace 聚合。
- **安全**：secrets 不进入模型上下文；代码执行无外网；SOC 2 Type II 路线图；企业版可 VPC 部署。

### 为什么不自己训模型

- 基础模型迭代以周为单位，自训必然落后。
- 真正的数据壁垒在「任务 → 模型 → 结果 → 采纳」的轨迹，而不在权重。
- 保持中立才能接入所有供应商，也才能在某个供应商断供时活着。

## 11. 商业模式

### 11.1 定价

| 计划 | 价格 | 包含 | 目标 |
|---|---|---|---|
| **Free** | $0 | 1 个 App，50 credits/月，预览带水印，不可导出 | 体验、传播 |
| **Maker** | $19/月（年付 $15） | 3 个 App，1,500 credits，TestFlight，代码导出 | 独立开发者 |
| **Studio** | $49/月 | 10 个 App，5,000 credits，3 席位，自定义域名，优先构建 | 小团队 |
| **Scale** | $199/月 | 无限 App，20,000 credits，10 席位，SSO，审计日志 | 成长型团队 |
| **Enterprise** | 定制 | 私有部署、私有设计库、SLA、专属算力 | 企业 |

**Credits 规则**：1 credit ≈ $0.01 的模型成本，按任务实际消耗计费；页面实时显示「本次预计消耗」。用完可单独充值，不强制升级。

**单次上架包**：$99/次（含构建、商店素材、审核辅导），给只做一次的用户。

### 11.2 单位经济（目标）

- Maker 用户月均模型成本：$6–9；毛利 55–68%。
- Studio 用户月均：$18–26；毛利 47–63%。
- 通过 prompt 缓存（30–50% 命中）、路由降级、批量 API 折扣，把毛利率推到 65%+。
- CAC 目标：$35（内容 + 模板 + 设计库 SEO）；LTV 目标：$240（12 个月 × $20）。

### 11.3 增长飞轮

```
真实界面库 → 更好的生成 → 更多可展示的 App → Gallery/社区 → SEO 与传播
      ↑                                                        ↓
      └──────────── 更多「模式有效性」数据 ← 更多上架 App ←──────┘
```

- **Gallery**：每个公开 App 都是一个落地页，带「用同样的起点做一个」按钮。
- **设计库 SEO**：`/design/onboarding/fintech` 这类页面获取长尾搜索。
- **模板**：不是静态模板，而是「可跑的起点」，复制即生成一个新项目。
- **MCP**：把 Mosaic 的设计检索与生成能力开放给 Claude Code / Cursor 用户，反向引流。

## 12. 路线图

### Phase 0（0–3 个月）：一条能走通的路

- 单用户、单项目、iOS。
- 一句话 → 3 页 → 真机预览 → 导出 Expo 工程。
- 接入 6 个模型（Opus 5.5、Fable 5、GPT-6.1 Sol、Gemini 4、DeepSeek V4.1、GPT Image 2.5）。
- 设计库 v0：5,000 条人工策展界面，支持检索与「应用 token」。
- 目标：20 个设计伙伴，10 个真实上架。

### Phase 1（3–6 个月）：从生成器到工作室

- App Graph、流程编辑、组件变体、代码视图。
- 后端一键开通（Auth / Postgres / Storage / Push）。
- TestFlight 自动构建；App Store 素材生成。
- 多人协作、评论、版本历史。
- 设计 lint + 参考溯源。
- 目标：200 个付费用户，MRR $8k。

### Phase 2（6–12 个月）：护城河

- Flow Completion、付费墙/Onboarding 专项。
- 多模型评审委员会 + 站内 eval 闭环。
- 设计库扩展到 10 万条；与 Mobbin 的正式合作（或自建）。
- Android + Web 导出。
- 增长数据回流（留存/转化基准）。
- 目标：1,000 付费，MRR $45k。

### Phase 3（12–18 个月）：平台化

- MCP / API：让外部 Agent 调用 Mosaic 的设计与构建能力。
- 模板/组件市场，创作者分成。
- 企业私有部署与私有设计库。
- 目标：MRR $150k，NPS > 50。

## 14. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 模型厂商自己做端到端 App Builder | 高 | 高 | 保持中立、多模型；把价值放在设计库、交付链、团队协作 |
| Mobbin 授权谈不下来 | 中 | 高 | 双轨：官方合作 + 自建策展库；先做 5k 条高信号数据 |
| 参考图版权/商标问题 | 中 | 高 | 只做模式抽取与元数据；不复制原图；明确归属与退出机制 |
| App Store 对 AI 生成 App 的审核收紧（4.2 / 5.1.1） | 高 | 中 | 生成真实功能而非空壳；内置合规检查；人工审核兜底 |
| 代码质量不足以进生产 | 高 | 高 | 限定技术栈；强类型 + 测试 + lint；导出干净工程；不承诺零人工 |
| 成本失控 | 中 | 高 | credits、预算上限、缓存、路由降级、批量折扣 |
| 同质化（大家都用同样的模型） | 高 | 中 | 设计数据 + 工作流 + 社区；品牌与品味 |
| 安全/隐私 | 中 | 高 | 沙箱、密钥隔离、SOC 2、企业 VPC、数据不训练 |

## 15. 下一步（两周内）

1. **锁定 3 个设计伙伴**：一个独立开发者、一个设计师、一个小团队；每周跟一次真实上架。
2. **做一条端到端窄链路**：习惯类 App，iOS，一句话 → 3 页 → Expo Go → TestFlight。
3. **建 500 条种子设计库**：只覆盖 5 个品类（习惯、记账、旅行、冥想、二手），但每条都人工标注模式。
4. **跑一次模型 bake-off**：同一组 20 个 UI 任务，比较 Fable 5 / Opus 5.5 / GPT-6.1 / Gemini 4 / DeepSeek V4.1 的一次通过率与成本。
5. **验证付费**：对 20 个目标用户做价格测试（$19 / $29 / $49），确认「上架」是不是比「生成」更强的付费点。
