# Mosaic 生产化清单

> 现在手上是「产品定义 + 高保真交互 + 设计系统」，不是「可用的 App 生成平台」。  
> 从 demo 到完全投入使用，缺的不是几个页面，而是六条真实链路：**生成、构建、设计数据、账户计费、合规上架、运维支持**。

- 版本：v1.0（2026-11）
- 关联：[产品规划](./product-plan.md) · [模型编排](./model-mesh.md) · [设计系统](./design-system.md)

---

## 0. 一句话判断

**最难的并不是让模型生成一个好看的页面，而是让生成结果稳定通过构建、装进真机、过 App Store 审核，并且单次成本可控。**

因此，生产化的第一原则是：**先跑通一条窄链路，再横向扩品类**。不要先做 20 个功能，再回头发现构建成功率只有 40%。

## 1. 当前成熟度

| 层 | 现在有什么 | 生产要求 | 判断 |
|---|---|---|---|
| 产品定义 | 定位、用户、流程、定价、路线图 | 可验证的 MVP 边界 | **75%** |
| 交互与视觉 | 五视图高保真原型、设计系统 | 真实状态、可访问性、组件库 | **65%** |
| 前端 | 静态 HTML/CSS/JS 原型 | Next.js/React、状态、实时、权限 | **25%** |
| 模型网关 | 路由设计文档 | 多供应商、计费、降级、评测 | **10%** |
| 代码生成 | 方案与 prompt 设计 | App Graph → 代码 → 类型检查 → 测试 | **5%** |
| 沙箱与构建 | 无 | microVM、EAS、签名、TestFlight | **0%** |
| 设计库 | 概念与 15 条演示数据 | Mobbin 授权 / 5k 条策展数据 / 检索 | **0%** |
| 账户与计费 | 无 | 登录、团队、credits、Stripe | **0%** |
| 安全与合规 | 原则 | 多租户隔离、密钥、隐私、DPA | **5%** |
| 上架与运营 | 流程演示 | Apple 账号、审核、支持、监控 | **5%** |

> 结论：**可以拿去融资、招人、找设计伙伴，但不能直接开放注册。**

## 2. P0：邀请前 20 个外部用户之前必须有

目标：一个用户从一句话开始，在 30 分钟内得到一个可安装到 iPhone 的 App，并且我们知道这次生成花了多少钱。

### 2.1 端到端窄链路

- [ ] 只支持 **iOS + 一个品类**（建议习惯追踪）
- [ ] 固定技术栈：Expo + TypeScript + Expo Router + NativeWind
- [ ] 输入一句话 → 澄清 ≤5 问 → 生成 3 个页面
- [ ] 真机预览：Expo Go 扫码，或 TestFlight
- [ ] 一键导出干净 GitHub 工程
- [ ] 自动构建 `.ipa` 并上传 TestFlight
- [ ] 失败可恢复：重试、回滚、查看日志

**验收**：10 个外部用户中，≥8 个能独立完成 3 页生成，≥6 个能装进自己的手机。

### 2.2 账户、项目与数据

- [ ] 邮箱 / Google / Apple 登录
- [ ] 工作区、项目、成员、角色（Owner / Editor / Viewer）
- [ ] 项目持久化：页面、组件、DNA、App Graph、构建记录
- [ ] 自动保存、版本历史、回滚
- [ ] 删除项目 / 导出数据 / 账户注销
- [ ] 基础空状态、加载状态、错误状态

**验收**：刷新、换设备、断线重连后，项目状态不丢。

### 2.3 模型网关与成本

- [ ] 统一 OpenAI-compatible 网关
- [ ] 首发接入 3–4 家：Anthropic、OpenAI、Google、DeepSeek
- [ ] 任务级路由 + fallback + 超时 + 限流
- [ ] 每次调用记录：模型、token、成本、延迟、是否采纳
- [ ] 项目 / 工作区 / 日三级预算
- [ ] 密钥只在网关侧，前端与沙箱不可见
- [ ] 供应商 429/5xx 自动切换

**验收**：单次 App 生成成本可查询，误差 < 10%；供应商故障时成功率仍 > 99%。

### 2.4 生成与构建

- [ ] App Graph schema（页面、组件、数据模型、接口、权限）
- [ ] Prompt Compiler：项目宪法 + DNA + 图谱切片 + 输出 schema
- [ ] 代码模板与组件库（不是让模型从零写所有东西）
- [ ] 生成后自动 `tsc` + ESLint + 单测 + Expo prebuild
- [ ] 构建失败自动修复循环（最多 2 次）
- [ ] 沙箱：Firecracker / E2B / Daytona，禁网、隔离文件系统
- [ ] 构建：EAS Build + 自动签名 + TestFlight

**验收**：一次构建通过率 > 80%；P95 首屏 < 90 秒；单 App 模型成本 < $6。

### 2.5 设计智能（最小版）

- [ ] 5,000 条人工策展界面（先覆盖 5 个品类）
- [ ] 检索：自然语言 + 平台 + 界面类型
- [ ] 每条记录：布局、组件、token、来源、许可状态
- [ ] 生成前引用 3–5 条参考，生成后可追溯
- [ ] 不缓存原图、不训练、不直接拼图

**验收**：设计参考能让生成结果的「模板感」显著下降；用户能说清楚为什么选这个参考。

### 2.6 合规、安全、法务

- [ ] 服务条款、隐私政策、DPA、子处理方清单
- [ ] 生成代码的 IP 归属写清楚
- [ ] 模型供应商条款与数据使用政策
- [ ] Apple Developer Program、EAS 凭证、隐私清单
- [ ] 沙箱逃逸、SSRF、prompt injection、供应链风险评审
- [ ] 内容安全与滥用举报
- [ ] 数据保留、删除、导出
- [ ] Mobbin 授权意向书或明确的 Plan B

**验收**：安全评审无 P0；法务文档可对外；Apple 账号与构建链路可用。

### 2.7 观测与支持

- [ ] 每次 Agent run 的 trace（模型、成本、耗时、diff）
- [ ] 错误追踪（Sentry）、结构化日志、告警
- [ ] 状态页 / 事故响应流程
- [ ] 应用内反馈、邮件支持、FAQ
- [ ] 管理员后台：用户、项目、成本、封禁、重跑

**验收**：任何一次失败都能在 5 分钟内定位到「模型 / 沙箱 / 构建 / 用户输入」哪一层。

## 5. 六条最难的生产链路

### 5.1 构建成功率

**为什么难**：模型生成的代码「看起来对」不等于能通过 TypeScript、Expo prebuild、原生依赖和签名。

**对策**：
- 限定技术栈，不让模型自由选库
- 组件库 + 模板 + 代码骨架，模型只填业务
- 生成后强制 `tsc`、lint、单测、prebuild
- 失败自动修复 ≤2 次，仍失败则降级到人工模板
- 建 50 条 Build Bench，按模型/任务统计一次通过率

**指标**：一次构建通过率 > 85%。

### 5.2 设计库授权

**为什么难**：Mobbin 的界面是别人的产品资产；没有授权不能缓存、不能训练、不能直接拼进成品。

**对策**：
- 优先官方 API / MCP 商业授权，按调用量或席位分成
- 只存元数据 + 缩略图 + 模式标签
- 明确归属、退出机制、不训练承诺
- Plan B：5,000 条人工策展 + 独立设计师分成，6–8 周可起量

**指标**：授权合同或 Plan B 数据达到 5k 条，且法务签字。

### 5.3 App Store 审核

**为什么难**：AI 生成 App 容易被 4.2（最低功能）、5.1.1（权限）、订阅合规、AI 内容政策卡住。

**对策**：
- 生成真实功能，不做空壳
- 权限延迟到使用时请求，写清用途
- 订阅页含价格、周期、取消方式、恢复购买
- 审核备注 + 演示账号 + 录屏
- 人工上架确认，不自动提交
- 建「审核被拒 → 条款 → 修复」知识库

**指标**：首次提交通过率 > 70%；被拒后 48 小时内可重提。

### 5.4 单位经济

**为什么难**：旗舰模型很贵，用户会反复重生成；一次 App 可能调用 30–80 次。

**对策**：
- credits 账本 + 预算上限
- 前缀缓存 + 结果缓存 + batch
- 高频微调走 DeepSeek / Gemini Flash
- 先生成 3 页，确认后再扩展
- 单 App 成本看板，按项目/用户/模型拆分

**指标**：单 App 模型成本 < $5；毛利率 > 55%。

### 5.5 安全

**为什么难**：执行用户/模型生成的代码，天然高危；还要防 prompt injection 和供应链攻击。

**对策**：
- microVM 隔离，默认禁网，白名单依赖
- 密钥不进沙箱，不进上下文
- 依赖锁定 + 漏洞扫描
- 多租户数据隔离 + RBAC
- 渗透测试 + 审计日志
- 对上传截图做 PII/恶意内容处理

**指标**：无沙箱逃逸、无跨租户访问、无密钥泄漏。

### 5.6 质量与信任

**为什么难**：用户不知道 AI 改了什么，也不知道该不该信。

**对策**：
- 每次改动展示 diff + 影响范围
- 设计参考可追溯
- 成本、模型、置信度可见
- 一键回滚
- 人工可接管任何一层（页面 / 组件 / 代码 / 数据）

**指标**：生成结果 24h 内被大改的比例 < 30%。

## 6. 前端产品化还缺什么

当前原型是静态壳，以下都要补：

- 认证、工作区、邀请、角色
- 真实项目列表、搜索、筛选、归档
- 生成中的流式状态、取消、重试、断点恢复
- 空状态、错误状态、权限拒绝、配额用尽
- 代码视图、diff、回滚、分支
- 真机预览、扫码、TestFlight 邀请
- 设置：模型策略、预算、数据政策、通知
- 账单：套餐、credits、发票、支付方式
- 团队：成员、评论、分享链接、审计
- 管理后台：用户、项目、成本、封禁、重跑
- 国际化：中 / 英、时区、货币
- 可访问性：键盘、焦点、屏幕阅读器、200% 缩放
- 设计系统落地为 React 组件 + tokens，而不是一次性 CSS

**不要**在 P0 做：复杂实时协作、插件市场、社交、移动端管理 App。

## 7. 技术落地顺序

```
Week 1–2   App Graph schema + 代码模板 + 3 个页面骨架
Week 3–4   模型网关 + 成本日志 + 沙箱 + tsc/测试
Week 5–6   Expo 预览 + EAS 构建 + TestFlight
Week 7–8   设计库 v0 + 参考注入 + 生成质量评估
Week 9–10  账户/项目/自动保存 + 预算 + 管理后台
Week 11–12 安全评审 + 法务 + 10 个设计伙伴 + 上线门禁
```

**原则**：每一周都要有一个能在真机运行的产物，而不是「后端全部做完再联调」。

## 8. 团队与预算

### 最小团队（3 个月，私人 Beta）

| 角色 | 人数 | 职责 |
|---|---|---|
| 产品 / 创始人 | 1 | 范围、设计伙伴、定价、法务 |
| 全栈 lead | 1 | Web、API、数据模型 |
| 后端 / 基础设施 | 1 | 沙箱、构建、队列、可观测 |
| AI / 代码生成 | 1 | Prompt、模板、评测、修复循环 |
| 产品设计 | 1 | 设计系统、真实状态、可用性 |
| QA / DevOps | 0.5 | 回归、发布、on-call |

### 成本粗算

- 人力是主要成本；3 个月 5–6 人。
- 模型 API：Beta 期 $3k–$10k。
- 基础设施：$2k–$5k/月（沙箱、构建、存储、DB）。
- Apple Developer $99/年；EAS / 监控 / 邮件等杂项。
- 预留 20% 安全与法务预算。

> 在中国做，3 个月人力约 ¥120–200 万；在美国约 $30–45 万。数字只用于量级判断。

## 9. 上线门禁

### Gate A：私人 Beta

- 10 个外部用户，8 个完成 3 页生成
- 6 个装进真机
- 构建成功率 > 80%
- 单 App 成本 < $6
- P0 安全 / 法务问题 = 0
- NPS > 30

### Gate B：公开 Beta

- 100 个项目，构建成功率 > 85%
- 付费转化 > 8%
- P95 首屏 < 90s
- 路由成功率 > 99.5%
- 7 日留存 > 25%
- 客服首次响应 < 4h

### Gate C：GA

- 1,000 个项目，月度构建 > 500
- 毛利率 > 55%
- 99.9% 可用性
- SOC 2 Type I
- 退款率 < 3%
-  App Store 首次通过率 > 70%

## 10. 现在不要做

- Android / Web 导出（先把 iOS 打穿）
- 插件 / 模板市场
- 企业 SSO / 私有化
- 自研基础模型 / 微调
- Figma 插件全量同步
- 实时多人协同（先做评论 + 版本）
- 社交 / 社区 / 创作者经济
- 复杂计费（先手动发票 + 简单 credits）

**每增加一个平台，构建矩阵和审核成本都会翻倍。**
