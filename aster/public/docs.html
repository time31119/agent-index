ASTER 开发者文档

ASTER 是一个同时兼容 OpenAI 与 Anthropic 协议的模型网关。你可以保留现有 SDK，只把 Base URL 指向网关，就能调用目录中的全部模型。

快速开始

三步完成接入：

  • 注册账号，在「令牌管理」创建一枚令牌（选择分组）。
  • 把 Base URL 改为 https://api.aster.dev/v1（本地部署时为 http://localhost:8787/v1）。
  • 用 Authorization: Bearer sk-ast-... 发起请求。

安装 SDK

pip install openai        # Python
npm install openai        # Node.js

第一次调用

curl https://api.aster.dev/v1/chat/completions \
  -H "Authorization: Bearer $ASTER_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "messages": [{"role": "user", "content": "你好"}]
  }'

鉴权

所有 /v1 接口都需要 API Key，支持两种请求头：

Authorization: Bearer sk-ast-xxxxx
# 或（Anthropic 客户端默认）
x-api-key: sk-ast-xxxxx

令牌可设置可用模型白名单、额度上限与过期时间。若 Key 泄漏，请在控制台立即停用或删除，并重新创建。

OpenAI 兼容

POST /v1/chat/completions，请求与响应结构与 OpenAI 完全一致，支持 messages、tools、tool_choice、temperature、max_tokens、stream。

from openai import OpenAI

client = OpenAI(api_key="sk-ast-...", base_url="https://api.aster.dev/v1")

resp = client.chat.completions.create(
    model="gpt-6-astra",
    messages=[{"role": "user", "content": "用一句话解释闭包"}],
)
print(resp.choices[0].message.content)

Anthropic 兼容

POST /v1/messages，与 Anthropic Messages API 结构一致，支持 system、tool_use、tool_result、stop_sequences、流式事件（message_start / content_block_delta / message_delta 等）。

from anthropic import Anthropic

client = Anthropic(api_key="sk-ast-...", base_url="https://api.aster.dev")

msg = client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "帮我审一下这段代码"}],
)
print(msg.content[0].text)

另有 POST /v1/messages/count_tokens 用于预估输入 token，返回 {"input_tokens": N}。

流式输出

设置 stream: true 后返回 SSE。OpenAI 协议以 data: {...} 分块并以 data: [DONE] 结束；Anthropic 协议以 event: + data: 成对返回。

stream = client.chat.completions.create(
    model="gemini-3-8-flash",
    messages=[{"role": "user", "content": "写一段冒泡排序"}],
    stream=True,
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="")

说明：当客户端协议与上游协议不一致时（例如用 OpenAI SDK 调用 Anthropic 上游），网关会在内部完成协议转换后再流式下发，首字延迟会略高于原生直连。

模型列表

GET /v1/models 返回当前令牌分组下可用的模型，可直接被 OpenAI SDK 的 client.models.list() 使用。

{
  "object": "list",
  "data": [
    { "id": "claude-sonnet-5-5", "object": "model", "owned_by": "Anthropic" }
  ]
}

Claude Code 配置

Claude Code 使用 Anthropic 原生协议，只需三个环境变量：

export ANTHROPIC_BASE_URL="https://api.aster.dev"
export ANTHROPIC_AUTH_TOKEN="sk-ast-..."
export ANTHROPIC_MODEL="claude-opus-5-5"

claude

若使用 Claude 桌面版或 VS Code 插件，在设置中把 API Base URL 指向同一地址，并填写同一个令牌即可。令牌分组需要包含你要使用的模型，否则会返回 model_not_in_group。

计费规则

费用按请求的实际 usage 计算，公式为：

费用 = (输入 tokens × 输入单价
      + 输出 tokens × 输出单价
      + 缓存读 tokens × 缓存读单价
      + 缓存写 tokens × 缓存写单价) × 分组倍率
  • 单价单位为「元 / 百万 tokens」，图片模型为「元 / 张」。
  • 金额内部以微元整数结算（1 元 = 1,000,000 微元），不存在浮点误差。
  • 请求失败（4xx/5xx）不计费；网关侧超时与上游错误不计费。
  • 余额不足时返回 402 insufficient_balance，充值后立即恢复。

自动化与状态

平台的核心运维动作由调度器自动完成，不需要人工值守：

  • 余额巡检与自动充值：余额低于阈值时自动充值（受月度上限保护），否则发送余额提醒。
  • 上游探活与故障转移：每 2 分钟探测一次渠道，连续 3 次失败自动下线并切换备用，恢复后自动上线。
  • 异常用量限流：单账户 10 分钟请求超阈值时自动限流，1 小时后自动恢复。
  • 月度开票：每月自动为有消费的账户生成发票，可在控制台下载。

所有自动处置都会写入审计日志，并在 服务状态页 对外公开。你可以通过 GET /api/public/status 获取同一份数据。

限流

默认每个令牌 600 请求 / 分钟，可在创建令牌时调整（10–6000）。并发较高时建议使用流式请求并实现指数退避。

服务等级

「高可用分组」承诺月度可用性 99.95%。未达标时，按当月该分组消费金额的 10% 进行额度补偿。计划内维护会提前 24 小时在控制台公告。

隐私政策

默认情况下，网关只记录请求的元数据（模型、token 数、耗时、状态码、费用），不记录 messages 内容。企业版可开启审计日志，或将网关私有化部署在自有 VPC 内。

我们不会将你的数据用于模型训练，也不会出售给第三方。支付信息由支付服务商处理，平台不存储银行卡信息。

服务条款
