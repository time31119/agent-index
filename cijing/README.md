# 词镜 · 说到哪，动到哪

单文件、零依赖的 9:16 短视频生成器原型。双击 `index.html` 即可运行，不需要装任何东西、不需要起服务。

内置样本就是那份 8 镜、45 秒的分镜头脚本《说到哪、动到哪，一条视频讲清楚》：

```
需求输入 → 结构化口播稿 → 触发词 → 词级时间戳 → 9:16 预览 → 时间线微调 → 导出
```

## 内置样本：8 个分镜

| 镜号 | 时间 | 触发词 → 画面 |
| --- | --- | --- |
| 01 | 0–4s | 「说到哪」出标题，「动到哪」箭头弹射 |
| 02 | 4–7s | 「数据」三根柱子依次升起 |
| 02 | 7–10s | 「步骤」三个节点依次连线 |
| 03 | 10–16s | 「截」弹出网页截图，「荧光笔」黄色高亮扫过 |
| 04 | 16–21s | 「产品」出产品名，「logo」圆形 Logo 弹入 |
| 05 | 21–27s | 「一句话」出公式，「时间戳」波形+播放头，「开关」红点亮起 |
| 06 | 27–34s | 「做法 / 第一种 / 第二种」两栏对照依次点亮 |
| 07 | 34–40s | 「字幕一识别」出时间线，「拖到对应词」素材吸附到位 |
| 08 | 40–45s | 「那个词 / 那一刻 / 出现」三个元素依次弹出，定格收尾 |

数据里的事件不写秒数，只写 `word: '数据'`、`step`、`hideAt`，生成时用 `findWordTime()`
在词级时间戳里找出这个词的时刻——改文案、改语速，触发点自动重算。

## 界面

| 区域 | 内容 |
| --- | --- |
| 左栏 | 文案需求、视觉事件开关（标题 / 数据 / 流程 / 引用 / 产品 / 原理）、音色、生成、口播稿列表（点击跳转） |
| 中栏 | 9:16 预览画布、播放条（可拖拽）、词级高亮字幕、当前句的词级时间条 |
| 右栏 | 模板包（3 套）、词级触发时间线（支持 − / ＋ 0.1s 微调）、导出信息 |

快捷键：`空格` 播放/暂停，`←` `→` 前后 1 秒。

## 已经真实可用的部分

- 三套模板包即时切换，切换后只显示该模板允许的视觉元素
- 词级时间戳、字幕逐词高亮、词级时间条
- 事件绑定触发词（`word`），生成时自动换算时间；同一场景可按词分步点亮（标题→箭头、公式→波形→红点）
- 时间线微调（− / ＋ 0.1s），点条目跳到该触发点
- 导出：分镜 JSON、字幕 SRT（真实文件下载）
- 口播稿 / 模板 / 导出弹窗的完整交互
- 试听配音：浏览器本地语音（Web Speech API）逐句朗读，🔊 开关，念完一句才进下一句

## 声音

原型一开始是**完全静音**的，原因有三个：

1. `API.tts()` 是空实现，没有返回音频，也没有 `<audio>` 元素；
2. 播放是 `requestAnimationFrame` 驱动的纯视觉时钟，和音频无关；
3. 导出也是模拟的，不会生成带音轨的 MP4。

现在加了一条零依赖的试听链路：用浏览器自带的 `speechSynthesis` 逐句朗读，
画面会停在句尾等这句念完（最多等 9 秒兜底），所以不会出现「下一句把上一句切断」。
如果 2.2 秒还没开口（机器上没有中文语音 / 被策略拦截），会自动关掉配音并提示。

它的局限：音色不受「② 配音音色」控制、没有词级时间戳、**导出的文件仍然没有声音**。
要真正出声，把 `API.tts()` 接上，返回 `{ audioUrl, words }`：

- 预览：把 `audioUrl` 塞进 `<audio>`，让 `loop()` 用 `audio.currentTime` 当时间轴；
- 字幕：用 `words` 替换 `buildWords()` 现在按字数估算的时间；
- 导出：`API.render()` 的产物带音轨，`下载视频` 按钮才指向真实文件。

浏览器自动播放策略：音频必须由用户手势触发，所以**要点一下 ▶ 才会出声**，打开页面不会自动播。

## 模拟的部分与接口位置

都在 `index.html` 的 `<script>` 顶部 `API` 对象里，返回 `null` 就走演示数据：

```js
API.rewrite(brief, events)   // TODO 大模型改写
// → { duration, segments: [{ t0, t1, text, events: [{ ev, at, step }] }] }

API.tts(text, voice)         // TODO TTS + 词级时间戳
// → { audioUrl, words: [{ w, t0, t1 }] }

API.render(storyboard)       // TODO Remotion / 云端渲染
// → { url }
```

- **rewrite**：接上后，`generate()` 会直接用返回的脚本，不再用内置示例。
- **tts**：接上后把 `words` 回填到 `segment.words`，字幕高亮即与该音频对齐；预览里把 `audioUrl` 塞进 `<audio>` 并让 `loop()` 用 `audio.currentTime` 驱动即可。
- **render**：接上后导出弹窗的「下载视频」按钮会指向真实文件。

调试用：`window.CIJING` 暴露了 `state`、`api`，以及
`CIJING.loadScript({ duration, segments })` 可以直接灌一份外部脚本（会自动补词级时间戳）。

## 文件

```
cijing/
├─ index.html   # 全部内容（HTML + CSS + JS）
└─ README.md
```

演示数据是这套 8 镜脚本：标题、柱状图、流程图、网页高亮、产品、原理波形、两栏对照、时间线吸附、结尾三连弹，
全部由 `events` 里的触发词驱动。

一个已知的取舍：第 06–08 镜的文案密度很高（45 秒里塞了 ~60 字/镜），按正常语速念不完。
本地语音会按句子密度自动提速（0.9–1.8 倍），仍有少量超出时画面会停在句尾等它念完。
接真实 TTS 后，建议按实际音频时长为这三镜多留 1–2 秒。
